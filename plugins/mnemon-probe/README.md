# dsh-agent-mnemon-probe

> 每轮报一行热记忆的**磁盘状态**：条数 / 字节 / 预算占比。
> **小探针，但它盯的是一个真洞。**

---

## 它防的是什么

**「标称」和「实际」不是一回事。**

热记忆（那种「每轮注入进提示」的短记忆文件）有个预算上限。你打开文件数一数：

```
标称：13 条 / 8,990 B / 占预算 87.8%
```

**看起来还好。但实测过一次：**

```
实际进入提示的：5 条
```

> ### ★ 差的 8 条去哪了？
> 它们还在磁盘上 —— **只是不再进入上下文了。**
> 而 agent 那边**不会有任何报错**，它只是**不再想起那 8 条**。

**这就是这个插件存在的理由**：那个「变少了」的过程是无声的，
所以你需要一个每轮都说一句「现在磁盘上是这样」的东西。

---

## 它报什么，不报什么

**★ 这一段比上面重要 —— 它是一个刻意的边界。**

| | |
|---|---|
| ✓ **报** | 文件在不在、多少字节、多少条、占预算百分之几 |
| ✗ **不报** | 「实际注入了几条」 |
| | **理由：拿不到。** |

**热记忆不走 system prompt** —— 它是被某个插件在运行时插进去的，
而**「插进去了几条」在磁盘上没有任何记录。**

**所以这个探针只报它能测的。** 它不会用一个估算值假装自己知道。

> ★ 一个测量工具最值钱的部分，是它**说得出自己测不到什么**。
> 报一个猜出来的「实际 5 条」，比不报更坏 —— 因为你会信它。

---

## 它长什么样

每轮在上下文里加一行，大意是：

```
[MNEMON 探针] MEMORY 14条/8.1KB(81%) ⚠接近上限 ｜ USER 10条/3.2KB(81%)
  ★ 接近/到达上限 —— 想加新条目前先精简
```

**★ 那句提醒是它的第二个作用**：它不只是报告数字，
它在你**该做决定的时候**说话（「接近上限了，想加新条目先精简」）。

---

## 装

```bash
dsh plugin --profile <name> add <path-to-this-package>
```

**装完要重启 DSH。**

### 一个可配项

```bash
MNEMON_RUNTIME   # 热记忆目录，默认 ~/.mnemon/runtime
```

**★ 为什么要做成可配的**：热记忆的真实路径**通常不在** `DSH_HOME` 下 ——
本项目第一次就找错了地方，所以这个值不写死。

---

## 一个用法：把它当尺子

```
改热记忆之前 → 看它报的数
改热记忆之后 → 再看一次
```

**它只是数字，但两个数字之间的差就是你的改动。**

---

## 边界

```
✗ 不报「实际注入几条」（拿不到，不猜）
✗ 不改任何东西 —— 只读
✗ 不做历史曲线 —— 它只有「现在」
✗ 不判断该删哪条 —— 那是你的判断，它只告诉你「快满了」
```
