# gateway —— 门与索引

> 一扇门搜全库：**只回指针 + 逐字片段，不做转述。**
> 账本建的是一手材料，这个负责把它们**取回来**。

---

## 它防的是什么

**「存下来了，但取不回来」——以及更坏的：「取回来了，但是别人转述的」。**

```
✗ 只有存储没有索引    → 你知道它在那儿，但你不知道在哪
✗ 用摘要回答         → 二手污染。摘要说「他当时不同意」，
                       原文说「这个方向先放一放」—— 差的不是措辞，是事实
✗ 猜一个地址         → ★ 错的门牌比没有门牌更坏（见下）
```

> ### ★ 所以它只有一条输出形式：**指针 + 逐字片段。**
> 它从不告诉你「大概是什么意思」，只告诉你「原文在这、原话是这个」。

---

## 三分钟上手

**★ 下面这五步是**真跑过**的（不是「应该能跑」）。**

```bash
# ① 建索引
node index.mjs
#    ★ 验：出现 index.json，输出「账本 N 条 ｜ 工作区 M 段」

# ② 现在什么样（时钟 / 有没有欠着的活）
node query.mjs now
#    ★ 验：一行时钟 + 账本条数 + 未结条数 + 最近一条

# ③ 搜一个词
node query.mjs 某个词
#    ★ 验：出来的是【地址 + 逐字片段】，不是一段概括

# ④ 用地址回原文
node query.mjs open file:notes/test.md#L1-33
#    ★ 验：打印那一段原文

# ⑤ 故意搜一个不存在的词
node query.mjs 完全不存在的词xyz
#    ★ 验：它说「没搜到」并给下一步 —— 而不是回空、也不是编一个
```

---

## 两种地址

```
ledger:<序号>              账本里的第几条（追加账本里序号是稳定的）
file:<相对路径>#L<a>-<b>    工作区某个文件的第 a–b 行
```

**★ 它们是**可解析的**，不是给人看的标签** —— `open` 直接认它们。

---

## ★ 一条纪律（比功能重要）

> **拿不到精确地址时，写「未知」并给一个检索入口，绝不猜。**

**理由**：错的地址**比没有地址危害更大** ——
它会返回错误内容，**而且在形式上与正确结果无法区分。**
被一个错误地址骗一次，你会开始怀疑所有地址。

**所以这个工具失败时说的话是这样的：**

```
✗ 没搜到「xxx」
  ★ 换个词再试；或者 node index.mjs 重建索引（新增的文件要重建才会进来）

✗ 还没有索引。先跑：node index.mjs
  ★ 检索不到东西时，它必须说清「缺什么」，而不是回空。
```

**★ 一个检索工具最值钱的部分，是它说得出自己为什么没结果。**

---

## 两个文件，为什么分开

```
index.mjs   索引构建器：把账本 + 工作区的 markdown 压成 index.json
query.mjs   门：搜、回地址、开原文
```

**★ 因为「建」慢而「查」必须快**：全量扫一遍工作区要几秒到几十秒。
**所以建的时候慢一次，查的时候一直快。**

**★ 副作用**：新增的文件要重建索引才会进来 —— 这一点它会在「搜不到」时提醒你。

---

## 它搜哪几层（现在）

```
L2  账本          每一条都带出处，是唯一「可裁决」的那一层
L3  一手层        工作区里的 markdown（按 40 行切段）
```

**★ 还没搜的**：会话日志索引、语义层。
**那些要额外的读取器**（会话日志是压缩的多帧格式，不是纯文本）。
**这个实现刻意只做通用格式** —— 你的日志格式可能和我们的不一样，
所以那一段留给你自己接：`index.mjs` 里加一个来源，往 `records` 里推就行。

---

## 边界

```
✗ 不转述 —— 只回指针与逐字片段
✗ 不猜地址 —— 拿不到就说「未知」
✗ 不做语义检索 —— 这是字面匹配；语义层是另一件事（mnemon 那一类）
✗ 不联网、不改任何东西 —— 纯读
```
