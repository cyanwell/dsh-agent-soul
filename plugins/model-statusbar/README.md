# dsh-agent-model-statusbar

> 侧边栏底部一张常驻小卡片：**本地模型服务现在是什么状态。**
> 进程在不在、接口通不通、显存占了多少、离自动静息还有多久。

---

## 它防的是什么

**「它还在占着显存，而你不知道」。**

本地跑模型（ComfyUI 这类）有个隐形的代价：

```
✓ 你在用的时候，它当然该在
✗ 你不用的时候，它【还在】—— 显存没释放，机器发热，别的活干不了
```

**而「不用了」这件事没有事件通知。** 你不会收到一条「你 20 分钟没出图了」——
所以显存就一直占着，**直到你想干别的事、发现干不了。**

> ### ★ 所以它做两件事：**把状态摆出来** + **到点自己收摊**。

---

## 两个功能

### ① 状态栏（常驻）

```
侧边栏底部
  └─ 本地模型  ● 就绪   显存 4.2G   12m 后静息
```

**有几种状态**：没起 / 启动中 / 就绪 / 忙碌 / 静息。
**显存占用是它最值钱的那一格** —— 那个数字直接决定你还能不能干别的。

### ② 空闲自动静息

**一段时间没有任何出图请求 → 自动把模型卸掉、进程留着。**

```
留进程   →  下次用不用冷启动（省几十秒）
卸模型   →  显存还给你（那才是你真正缺的东西）
```

**★ 为什么是「静息」而不是「关闭」**：两者的代价差得很远。
**冷启动要重新读模型（几十 GB 的磁盘 I/O）**，而静息只是卸载显存里的权重。
**所以默认动作应该是省掉最贵的那一步，而不是把一切都关掉。**

---

## 一条纪律：**状态查询不许拖慢主进程**

它读服务状态的方式是**外部探测**（子进程 / 短超时 HTTP），
**绝不在主进程里做同步阻塞调用。**

```
✗ 一个卡住的 HTTP 请求 → 整个界面卡住
✓ 探测跑在子进程、带超时，拿不到就报「未知」
```

**★ 判据同 `dsh-agent-echo`：一个状态栏永远不该成为它监视的那个系统的负担。**

---

## 装

```bash
dsh plugin --profile <name> add <path-to-this-package>
```

**装完要重启 DSH。**

### 可配项

```bash
STATUSBAR_STATE   状态文件路径（记录静息倒计时等）
COMFYUI_HOST      本地模型服务地址，默认 127.0.0.1:8188
COMFYUI_DIR       服务安装目录（用于启动与找日志）
```

**★ 它默认**不**主动拉起服务** —— 拉起是另一个插件的职责。
它只报告与静息；**「要不要现在启动」是你的决定，不是状态栏的决定。**

## 自检

```bash
node selftest.mjs
```

（Windows 上另有一个 `probe.ps1`，用来在命令行单独探一次服务状态。）

---

## 边界

```
✗ 不启动服务 —— 只报告 + 静息（启动的触发权在别处）
✗ 不猜状态 —— 探测拿不到就报「未知」，不报一个猜出来的绿
✗ 不做历史曲线 —— 只有「现在」
✗ 不占主进程 —— 探测永远在子进程、永远带超时
```
