# dsh-agent-memory

> 把**活时钟**与一层**定长自我层**推进每一步的提示里 ——
> 让一个回合制的 agent 不必「记得要去查」，也能知道现在是什么时候、自己是谁。

---

## 它防的是什么

**拉取式记忆的瓶颈不是「取不到」，是「不知道要去取」。**

给 agent 配一扇检索门（一个能搜全库的命令），大概是所有记忆方案的第一步。
但那扇门是**拉取式**的：它在那儿，很好用，**可是得有人想起来去开它**。

一个回合制的 agent 有个具体的形状：

```
只有人说话才醒来 → 醒了不知道现在几点、上一次说话隔了多久
                → 于是它不会主动去查，因为它【不知道自己错过了什么】
```

**所以真正的缺口不在检索精度上，在触发上。**
而这个包补的正是触发：**把「知道」做成推送，而不是靠 agent 想起来。**

---

## 它怎么做

在**每一步模型调用之前**，往提示里插一段运行时上下文。

两步都是纯读：

```
① 读一个「状态」文件（时钟 / 距上轮 / 未结项 …）
② 读一份「自我层」文件，全文插入
```

**关键一条：它不生成内容，只搬运。** 那两个文件由你自己维护 ——
这个包不替你写「我是谁」，它只保证**每一步都读得到**。

---

## 为什么自我层要「定长」

因为它**每轮都注入**，所以稳定的前缀才便宜（prefix cache）。

这条约束会反过来决定怎么写那份文件：

```
✓ 不变量写死在文件里     —— 它每轮都一样，落在缓存前缀里
✓ 变动的东西由脚本刷新   —— 时钟、未结项这类，让它去变
✗ 不要把长篇内容塞进来   —— 每一轮都要重新读一遍，你为它付每一次的钱
```

**一句话：这份文件是「最不能丢的东西」的寄存处，不是日记本。**

---

## 它还会注入一条「门牌条款」

除了上面两样，它还会在上下文里放一条纪律 —— 大意是：

> 所有压缩 / 裁剪 / 摘要类的产物，**必须带得回原文的指针**。

**为什么这条要由一个插件来推**：因为压缩是**自动**发生的。
等到 agent 想起来「我该标注来源」的时候，摘要已经写完了。

**这条纪律和另外两个零件是配套的**（见 `dsh-agent-compaction` / `dsh-agent-pruner`）——
那两个负责在产物里**写**指针，这个负责让 agent **知道要写**。

---

## 装

```bash
dsh plugin --profile <name> add <path-to-this-package>
```

**装完要重启 DSH**（宿主半只在进程启动时加载一次）。

### ★ 两个必配项

```yaml
# cordis.patch.yml
- id: dsh-agent-memory
  name: 'dsh-agent-memory'
  config:
    selfPath:  './SELF.md'      # ← 你的自我层文件
    statePath: './state.json'   # ← 你的状态文件
```

**默认值是占位符，必须改成你自己的路径。**
理由很直接：这个包不知道你是谁，**它假定你已经写好了一份「最不能丢的东西」的清单** ——
那份清单长什么样、放在哪，是使用者的事，不该由插件替他决定。

**★ 判据**：装完之后，每一步的模型调用里应该能看到那段运行时上下文
（默认叫 `agent:self`）。看不到 → 没生效。

---

## 一个副产物：把「门牌」变成条款

它注入的那条纪律，与另外两个零件的分工是这样的：

| | 干什么 |
|---|---|
| `dsh-agent-memory` | **让 agent 知道**要写指针（推送条款） |
| `dsh-agent-compaction` | 在**压缩**产物里**写**指针 |
| `dsh-agent-pruner` | 在**裁剪**产物里**写**指针 |

**三者独立可装。** 只装条款，agent 会知道要写但没人替它写；
只装写入方，指针会写出来但 agent 未必知道那是必须的。

---

## 边界

```
✗ 不生成内容 —— 它只搬运你写好的两个文件
✗ 不写任何东西 —— 只读（statePath 由你自己的脚本去更新）
✗ 不碰记忆库 —— 检索仍然是拉取式的，这个包不改变那套
✗ 不注册改变 agent 行为的钩子 —— 它只往提示里加一段上下文
```
