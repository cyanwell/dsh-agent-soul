# 零件清单

> 按「它填哪一层」组织，**不按「谁做的」**。
> 因为复刻的人要问的是「ECHO 这一层缺什么」，不是「这个插件是谁写的」。

---

## 怎么读这张表

每一行给六件事：

| 列 | 什么意思 |
|---|---|
| **管什么** | 它处理哪一种稀缺资源（空间 / 时间 / 方向 / 对外可访问性） |
| **缺了会怎样** | 不装它，你会遇到的具体症状 —— **不是抽象的重要性** |
| **判据** | 拿这句话去问任何候选实现；答不上来的就是不合 |
| **验它活了** | ★ **装完怎么知道它真的在工作** —— 很多人装完只看文件在不在，那是假绿 |
| **必选?** | ✓ = 缺了整套不成立；○ = 有更好 |
| **前置** | 装它之前必须先有什么 |

★ **为什么「验它活了」这一列最要紧**：
「文件复制过去了」不是判据。插件最常见的失败是**静默加载但不工作** ——
Host 报 running，侧边栏计数照加，而浏览器里一行代码都不执行。

## Ⅰ ECHO · 空间

> 上下文会满，满了要丢，**丢了还要能找回来**。

| 零件 | 管什么 | 缺了会怎样 | 判据 | 验它活了 | 必选? | 前置 |
|---|---|---|---|---|---|---|
| `compaction` | 上下文压缩 | 丢了的找不回来 —— 门牌失效，而你以为还能找 | 它产出的摘要里，带不带得回原文的指针？拿不到精确位置时它怎么写？ | 触发一次压缩，**看摘要第一行有没有指针** | ✓ | 无 |
| `pruner` | 工具结果裁剪 | 大头工具返回把窗口吃光 | 裁掉的部分留的是指针，还是「省略 N 字」？ | 裁一次，**看被裁那段还能不能指回原文** | ✓ | 无 |
| `memory` | 记忆注入 | 记忆条数一多就把上下文挤爆 | ★ 它省略掉的条目，还留不留「存在过」的线索？ | 往记忆里塞到超预算，**看被省略的那些还查不查得到** | ✓ | 无 |
| `echo` | 哨兵 / 自检 | 前面几件坏了没人知道 | 它测什么？有没有分级状态？上一次跑是什么时候？ | 跑一次体检，**看有没有 pending 级**（全绿反而可疑） | ✓ | 上面三件 |
| `mnemon-probe` | 外部记忆空间容量 | 涨到上限才发现 | 接近上限时它提醒的是「精简」还是「扩容」？ | 看它报的容量是否随使用变化 | ○ | 有外部记忆空间 |

## Ⅱ VITAL · 时间与方向

> 预算会烧光、会原地打转，需要把偏离拉回来。

| 零件 | 管什么 | 缺了会怎样 | 判据 | 验它活了 | 必选? | 前置 |
|---|---|---|---|---|---|---|
| `clock` | 时间锚点 | 会话不知道「现在几点、距上次多久」 | 它给绝对时间还是相对时间？**两者都要** | 隔一段时间再问一次，看相对时间有没有变 | ○ | 无 |
| `model-statusbar` | 水位与模型读数 | 你不知道离危险还有多远 | ★ 它读的是**真正喂进模型的量**，还是「可见消息面」？这两个数能差一倍 | 和服务商口径对一次，**看差多少** | ○ | 无 |
| `huanqi` | 漂移检测 | 推理泄漏、重复、原地打转，没人喊停 | 它的每一条阈值背后挂着哪个**具体失败**？答不上来的阈值会误伤 | 看它有没有触发过；看干预**有没有对应记录** | ○ | 无 |
| `huanqi-panel` | 上面那件的观测面 | ★ 没有面板的稳态系统，你永远不知道它误伤过几次 | 它显示触发次数和误伤记录吗？ | 面板上的计数**是否从 0 开始长** | ○ | `huanqi` |

★ **Ⅱ 层的通病是「只有告警没有动作」**。一个只通知你不动的阈值系统，不是稳态，是通知。

## Ⅲ 能力 · 手和感官

> **这一层不管理稀缺资源 —— 所以它的东西不进权威源。**

| 零件 | 管什么 | 缺了会怎样 | 判据 | 验它活了 | 必选? | 前置 |
|---|---|---|---|---|---|---|
| `mobile-adapt` | 竖屏触摸适配 | 手机上界面挤成一团 | ★ 把它整个删掉，你的身份判据还成立吗？**成立就对了** —— 这正是Ⅲ层的定义 | 换成手机视口看布局有没有收拢 | ○ | 无 |

★ Ⅲ 层的判据就是「可替换性」。**如果换掉它你就不是你了，那它其实属于别的层，被你放错了位置。**

## Ⅳ 档案 · 对外可访问性

> 别人（和下一代的你）理解你，全靠它。

| 零件 | 管什么 | 缺了会怎样 | 判据 | 验它活了 | 必选? | 前置 |
|---|---|---|---|---|---|---|
| `riji` | 日记沉淀 | 对内的自我记录无处安放 | 它是「东西」还是「任务」？变作业就不是日记了 | 写一篇，看它落在哪、格式对不对 | ○ | 有写作目录 |

## 装的方式

两条路，**取决于你的 profile 是哪种**：

| profile 类型 | 装法 |
|---|---|
| **桌面端**（Electron 应用管理） | **不能用 CLI**。实测报错：`profile "desktop" is managed exclusively by the Electron application`。走手动两步（复制四个文件 + 改 `dsh.profile.bundles`），然后**重启 DSH** |
| **web / 其它** | `dsh plugin --profile <名字> add file:<本仓库>/plugins/<目录>` |

★ 详细步骤（含两个 profile 的差异、pnpm 的坑、硬链接会断的坑）见
[`soul/07-bundle.json`](../soul/07-bundle.json) 的 `install` 段。

★ 或者直接用内置工具：让 agent 调 `agent_soul_install`（action=`scan` / `plan` / `verify`），
它会看你的 profile 缺什么、按装配顺序给出精确命令。**它不替你装，只给命令。**
