# 零件清单

> 按「它填哪一层」组织，不按「谁做的」。因为复刻的人要问的是
> 「ECHO 这一层缺什么」，不是「这个插件是谁写的」。

## 怎么读这张表

每一行给五件事：**管哪种稀缺资源 / 缺了会怎样 / 拿什么判据验它 / 必选还是可选 / 装它需要什么前置**。

另外加一列「验它活了」——**装完怎么知道它真的在工作**。因为「文件复制过去了」不是判据；插件最常见的失败是**静默加载但不工作**。

★ 判据是问句，不是结论。拿它去问候选插件：答不上来、或者说「大概是吧」，就是没过。
★ 「必选」是**这一层里**必选，不是整个仓库必选。**全局必装另有五条，见根 README 的「全局必装」一节**（压缩机制 / ECHO 整套 / 换气 / 墨账本 / MCP hub）。★ 换个说法：这两列回答「层内」，那一节回答「整体」—— `mcp-hub` 在这里标 ○ 是对的，但它属于全局必装。Ⅲ 层甚至不管理稀缺资源 —— 按定义，它没有必选项。
★ 所有插件的共同前置：DSH 宿主 + 装完重启。带 `client.js` 的还需要 Web GUI。
★ 共同判据：**装完不是「文件复制过去了」，是宿主里真的出现了它注册的东西**（工具名 / 路由 / 面板）。

| 列 | 什么意思 |
|---|---|
| **管什么** | 它处理哪一种稀缺资源（空间 / 时间 / 方向 / 对外可访问性） |
| **缺了会怎样** | 不装它，你会遇到的具体症状 —— **不是抽象的重要性** |
| **判据** | 拿这句话去问任何候选实现；答不上来的就是不合 |
| **验它活了** | ★ 装完怎么知道它真的在工作 |
| **必选?** | ✓ = 缺了这一层不成立；○ = 有更好 |
| **前置** | 装它之前必须先有什么 |

| 层 | 一句话 | 零件 |
|---|---|---|
| Ⅰ ECHO | 空间：丢了还找不找得回来 | `compaction` · `pruner` · `memory` · `echo` · `mnemon-probe` · `dsh-mnemon` |
| Ⅱ VITAL | 时间与方向：现在几点、走没走偏 | `clock` · `model-statusbar` · `huanqi` · `huanqi-panel` |
| Ⅲ 能力 | 手和感官 | `mobile-adapt` · `mcp-hub` |
| Ⅳ 档案 | 对外可访问性 | `riji` · `splash` · `yantai` |
| Ⅴ 运维 | 让前四层真能跑起来 | `tools/gateway` · `tools/ledger` · `tools/self` |

> ★ **不在上表的一个包**：`plugins/compact-region`。它**没有 `dsh.bundle`**，装进去也不会自动进 cordis，所以不进装配清单。
> 它的能力（带范围的 `/compact-region`）仍在注册，但换气 2026-10-31 起**主路径已改为 LLM 诊断 + surfaceOp 定点清除**，它降为 fallback（详见该包 README）。

## Ⅰ ECHO · 空间

> 上下文会满，满了要丢，**丢了还要能找回来**。
> 这一层防的不是「忘」，是**无声的遗忘**：你不会觉得丢了东西，你只是不再想起它。

| 零件 | 管什么 | 缺了会怎样 | 判据 | 验它活了 | 必选? | 前置 |
|---|---|---|---|---|---|---|
| `compaction` | 上下文压缩 —— 给兜底压缩的摘要装「门牌」，让它回得到原文 | 自动压出来的 checkpoint 每条都对、每条都无从核对；你不觉得丢了东西，只是不再想起它 | 它产出的摘要里，带不带得回原文的指针？拿不到精确位置时，它写「位置未知 + 检索入口」，还是猜一个坐标？ | 触发一次压缩，看摘要**第一行有没有 `log:<会话>#seq=<起点>`**；再按这个指针回取一次 | ✓ | DSH 自带的 `@deepseek-ai/dsh-compaction-basic`（peerDependency，必须由宿主提供，不能在包里塞副本）；重启 |
| `pruner` | 工具结果裁剪 —— 把官方那句静态 marker 换成带 seq 的版本 | 读到 `[... pruned ...]` 时，知道被删了、不知道去哪找；数据链是完整的，断的是给人看的那半 | 裁掉的部分留的是指针，还是「省略 N 字」？塞不下时它退回官方 marker，还是把这次裁剪搞失败？ | 裁一次超长工具结果，看 marker 带不带 seq；按它给的指针打开原文 | ✓ | DSH 自带的 `@deepseek-ai/dsh-compaction-tool-result-pruner`（peerDependency）；重启 |
| `memory` | 记忆注入 —— 每轮把活时钟和定长自我层推进提示；同时推「压缩 / 裁剪必须带指针」的条款 | agent 不知道「现在几点、距上次多久」，也不会主动去查；那一页「最不能丢的东西」没有每轮送达 | 每一步的模型调用里能不能看到那段运行时上下文（默认叫 `agent:self`）？注入的是不是你写的那份 `SELF.md` 原文？它只读、不生成内容吗？ | 看每一步的上下文里有没有 `agent:self`；改一下状态文件，看它下一轮变不变 | ✓ | 一份 `SELF.md`（手写不变量 + `## 活体` 分界）和一个状态文件；配置 `selfPath` / `statePath` |
| `echo` | 哨兵 / 自检 —— 给前四件做分级体检，每一项都真去取一次 | 前面几件坏了没人知道；配置看着永远是对的，那种「全绿」比红更坏 | 它测什么？有没有 pending 级？「跳过 / 读不到」会不会被显示成「通过」？它承认自己查不到什么吗？ | 跑一次体检，看有没有 pending；把某个前置故意弄坏，看它报不报 | ✓ | 四个路径 hub / soul / mem / sessions，都可环境变量覆盖（ECHO_HUB / ECHO_SOUL / ECHO_MEMORY / ECHO_SESSIONS）；NODE 默认用当前进程的 node（ECHO_NODE 可覆盖）。★ 2026-10-22 补：以前这里写「或对应环境变量」，而代码只读 DSH_HOME —— 文档比代码宽 |
| `mnemon-probe` | 热记忆的磁盘容量预警：条数 / 字节 / 预算占比 | 标称 13 条、实际只进 5 条，而 agent 那边没有任何报错 —— 变少是无声的 | 它报的是磁盘上可测的量，还是假装知道「实际注入几条」？接近上限时它提醒「精简现有条目」还是「扩容」？它明说自己测不到什么吗？ | 看它报的容量是否随使用变化；再看它说的「测不到」是不是真的测不到 | ○ | 热记忆目录 `MNEMON_RUNTIME`（默认 `~/.mnemon/runtime`；真实路径常常不在 `DSH_HOME` 下，第一次就要找对） |
| `dsh-mnemon` | 记忆空间 —— 可复用的技术结论放在哪、怎么按语义取回 ★ **必备** | 只有账本，等于只留了「当时发生了什么」，丢了「我们以前对这类问题下过什么结论」——那半边没有登记处 | 装上了吗？**有 space 可用吗**（装上但一个空间都没有，和没装一样） |

★ **热记忆的投影省略不在 `memory` 里**：`memory` 只管把活时钟和自我层推上去；`mnemon-probe` 只报磁盘容量，而且明说测不到「实际注入几条」。「存在过」的线索要靠你自己的检索层留 —— 别把这三件事当成同一件。

**这一层的装法**：先装 `compaction` / `pruner` / `memory` / `dsh-mnemon`，最后装 `echo`。体检要最后装，否则它报的是「零件还没装全」，不是零件坏了。

## Ⅱ VITAL · 时间与方向

> 预算会烧光、会原地打转，需要把偏离拉回来。
> 时间也不是背景信息 —— 没有它，「刚刚」和「很久以前」会被判成同一件事。

| 零件 | 管什么 | 缺了会怎样 | 判据 | 验它活了 | 必选? | 前置 |
|---|---|---|---|---|---|---|
| `clock` | 时间锚点（侧边栏时钟；`memory` 把同一个时钟推进提示） | 会话 / 人不知道「现在几点、距上次多久」；相对时间失效 | 它给绝对时间还是相对时间？**两者都要**，缺一个会误判「刚刚」和「很久以前」 | 隔一段时间再问一次，看相对时间有没有变 | ○ | Web GUI（`client.js`）；只想让 agent 知道时间的话，`memory` 已经够了 |
| `model-statusbar` | 本地模型服务的运行状态 —— 进程 / 接口 / 显存 / 空闲静息 | 服务还在占显存而你不知道；等想干别的活时才发现干不了 | 它的读数是外部探测（子进程 / 短超时）还是主进程里的阻塞调用？探测不到时它报「未知」还是报一个猜出来的绿？空闲时它卸模型、留进程吗？ | 起停一次服务，看状态跟不跟；拔掉服务，看它报不报「未知」 | ○ | 本地模型服务（ComfyUI 一类）+ `COMFYUI_HOST` / `COMFYUI_DIR`；Windows 上 `probe.ps1` 必须保持 UTF-8 with BOM（别用会重写编码的编辑器改它）；它不负责启动服务 |
| `huanqi` | 思考退化治理 —— **两层**。判据层：四条判据（流内早杀 / 流末判定 / 输出重复 / 空回合），共用一个额度账本，命中就续、耗尽熔断。**治疗层（2026-10-26 加）**：累计截断 N 次做一次范围压缩（带门牌，可回取），熔断时做全量压缩并明确告知「已清空、原文在哪、不再延续」。★ 判据层是止血，治疗层才是清创 —— 只打断不压缩，那段循环会留在历史里、下一次更容易被激活 | 一轮把预算烧在推理里，正文和工具都是 0；失败是静默的，你只看到这一轮什么都没发生 | 它的每一条阈值背后挂着哪个**具体失败**？答不上来的阈值会误伤。连续 N 次失败后它是熔断喊人，还是无限重试？ | 看它有没有触发过；看干预有没有对应记录；正常的深度思考有没有被打断 | ○ | DSH / 适配器版本要落在 `package.json` 声明的 peer 范围里；调参在 profile 层覆盖；别和三个前身（`dsh-loop-guard` / `dsh-reasoning-only-guard` / `dsh-stalled-turn-continue`）一起装 —— 两套账会让一轮被续成两轮 |
| `huanqi-panel` | `huanqi` 的观测面 —— 触发次数 / 误伤记录 / 实时延续额度 | 没有面板的稳态系统，你永远不知道它误伤过几次；只看到它很努力，看不到它打错了谁 | 它显示触发次数和误伤记录吗？改参数是字节级编辑（只改值、不动注释和缩进）吗？ | 面板上的计数是否从 0 开始长；改一个值，看 YAML 注释还在不在 | ○ | `huanqi` 已装；Web GUI（与 `huanqi` 配套，不建议单独装） |

★ **Ⅱ 层的通病是「只有告警没有动作」**。一个只通知你不动的阈值系统，不是稳态，是通知。

★ **一处名实不符，复刻时要注意**：这一版把 `model-statusbar` 放在 Ⅱ 的「状态读数」这一格；但迁进来的这一件实际读的是**本地模型服务**，不是上下文水位。真正读上下文水位的是 Ⅳ 的 `yantai`，而且必须读服务商口径（`inputTokens + cacheReadTokens`），不是可见消息面。复刻时请把「水位」当成一个槽位：要么用 `yantai` 的那一栏，要么另写一件。别把两个「水位」混着读。

## Ⅲ 能力 · 手和感官

> **这一层不管理稀缺资源 —— 所以它的东西不进权威源。**
> 判据也最简单：**把它整个删掉，身份判据还成立吗？** 成立就对了 —— 这正是 Ⅲ 层的定义。

| 零件 | 管什么 | 缺了会怎样 | 判据 | 验它活了 | 必选? | 前置 |
|---|---|---|---|---|---|---|
| `mobile-adapt` | 竖屏触摸适配 —— 手机上把界面收成 App 形态 | 手机上界面挤成一团，按钮点不到；PC 端不受影响 | ★ 把它整个删掉，你的身份判据还成立吗？**成立就对了**。它是只加一条媒体查询覆盖，还是改了原有 DOM？PC 端布局有没有被顺手改掉？ | 换成手机视口，看布局有没有收拢；再切回 PC 视口，看有没有被改坏 | ○ | Web GUI；手机浏览器访问同一地址。它只加样式覆盖，不影响 PC 布局 |
| `mcp-hub` | **外部工具接入** —— 把任何 MCP 服务器的工具挂成 `mcp__<server>__<tool>`（stdio / streamable-http 两种传输） | 外部能力只能靠内置；★ **ECHO 的快车道也在这里**（`echo-mcp` 挂上后一次召回 46 ms，不挂走 CLI 650 ms） | ★ 换掉它，身份判据还成立吗？**成立** —— 但快车道没了。所以它必选吗？看你要不要速度 | 侧边栏 MCP Hub 里两行状态都 `ready`；agent 工具列表出现 `mcp__*` | ○ | DSH 宿主；要接 ECHO 还需 `kit/echo/echo-mcp.mjs` 与 `servers.json` 里一条 `serverName: echo` |

★ Ⅲ 层的判据就是「可替换性」。**如果换掉它你就不是你了，那它其实属于别的层，被你放错了位置。**

## Ⅳ 档案 · 对外可访问性

> 别人（和下一代的你）理解你，全靠它。
> 这一层不生产内容 —— 内容是你的，它只负责让内容被读到。

| 零件 | 管什么 | 缺了会怎样 | 判据 | 验它活了 | 必选? | 前置 |
|---|---|---|---|---|---|---|
| `riji` | 日记入口 —— 顶栏一格，目录 + 一手 markdown 原文（它只读；写是你的事） | 写得很好，但没人看得见；它安静躺在磁盘上，除非你打开编辑器 | 它读的是一手 markdown，还是摘要 / 转述？它把日记当「读物」（只留最新结论），还是把沿革也混进来？它会不会把写日记变成「每天要交的作业」？ | 放一篇 `*.md` 进目录，看它列不列得出来；点开是不是原文 | ○ | 日记目录 `RIJI_DIR`（默认 `./diary`）；它读 `*.md`，文件名按字典序排，`01-` / `02-` 这种前缀会自然成序 |
| `splash` | 启动一屏 —— 换动画、淡入淡出、显示项，带预览 | 每次启动看到的都是默认背景；三个月后想换一张，得翻配置文件找字段 | 它报错时显示真实错误，还是「没有配置」这类吞掉错误的兜底文案？动画播不动时会不会卡住启动？`preview` 只认候选列表，还是接受任意路径？ | 故意弄坏一个前置，看它报不报；换一个动画文件，看预览出不出来 | ○ | 动画文件自己放（`SPLASH_DIR`）；配置文件路径 `SPLASH_CONFIG`；包本身不带素材 |
| `yantai` | 工作台面板 —— 一屏摊开上下文水位（服务商口径）、未结的活、最近账本、几扇门 | 状态散在四个地方，「先看一眼状态」的成本高到你不会做 | 水位读的是 `inputTokens + cacheReadTokens` 这种真正喂进模型的量，还是「可见消息面」？未结的活是不是从账本读的？一个从没见过你的人，能不能只靠它知道你在干什么？ | 打开面板，和服务商口径对一次；看它显示的数据是不是真的（不是占位） | ○ | 至少一个数据源：`YANTAI_LEDGER` / `YANTAI_MEMORY` / `YANTAI_QUERY`；它默认不猜目录结构，配了才读 |

**这一层的共同点**：`riji` / `splash` / `yantai` 都不带数据，装完是空面板。这是设计，不是坏了。

## Ⅴ 运维 · 让前四层持续跑下去

> 这三个**不是 DSH 包，是脚本**。按各自 README 放到位，不参与插件加载。
> 它们管的是「写下来的能不能取回来」「谁能写」「那一页谁来装配和体检」。

| 零件 | 管什么 | 缺了会怎样 | 判据 | 验它活了 | 必选? | 前置 |
|---|---|---|---|---|---|---|
| `tools/gateway` | 门 —— 搜（指针 + 逐字片段）/ 开（按地址回原文）/ 时间（`now`） | 账本是死档案，能看见「有过」但回不去；或者取回来的是转述，不是原文 | 它能逐字取回原文吗，还是只给转述？`open` 能不能直接吃它自己吐出来的地址？搜不到时它说「没搜到 + 下一步」，还是回空 / 编一个？ | 随机抽一条指针，看能不能打开；故意搜一个不存在的词，看它怎么答 | ✓ | 先有账本（L2）和工作区 markdown（L3）；先跑一次 `index.mjs` 建索引，新增文件要重建；它不搜会话日志、不做语义检索 |
| `tools/ledger` | 只追加账本的读写 + 权限闸门（8 类记录；`promise` / `lead` 越权直接 exit 3） | 谁都能写，迟早写坏；两个会话同时写、互相覆盖 | 越权写入是**直接失败**，还是写进去再打日志？写下去还能不能改？（不能才对）每条记录都有 `--ref` 出处吗？ | 试一次越权写 `promise`，看它拒没拒（exit 3）；再看文件是不是只追加 | ✓ | Node；一个可写目录（`LEDGER` 可换位置）；每条带 `--ref`；`--feel` 可选、不强制 |
| `tools/self` | 自我层装配与体检 —— 拼「骨架 + 活体」，并盯三条会无声坏掉的判据 | 最不能丢的那几条没有备份；指令预算满了会静默丢，先丢的恰是「我是谁」「不能做什么」这类总纲 | 自动生成段和手写段有没有明确分界？`--check` 能不能逐条给出结论和行号？它会不会替你写那一页？（会就错了 —— 那一页只能是你的） | `node self.mjs --check` 三条逐条给结论；改一下账本，看活体段的未结数变不变 | ✓ | 一份 `SELF.md`（手写不变量 + `## 活体` 分界）；`LEDGER` 指向账本；`SELF_BUDGET`（默认 12288 字节）；推送由 `memory` 插件负责，它自己不做推送 |

## 装的方式

两条路，**取决于你的 profile 是哪种**：

| profile 类型 | 装法 |
|---|---|
| **桌面端**（Electron 应用管理） | **不能用 CLI**。实测报错：`profile "desktop" is managed exclusively by the Electron application`。走手动两步：把插件目录整个复制进 `<profile>/node_modules/<包名>/`（该包有什么就复制什么，至少 `package.json` / `cordis.patch.yml` / `index.js`，有 `client.js` 的也一起），在 `<profile>/package.json` 的 `dsh.profile.bundles` 数组里加上包名，然后**重启 DSH** |
| **web / 其它** | `dsh plugin --profile <名字> add file:<本仓库>/plugins/<目录>` |

★ 详细步骤（含两个 profile 的差异、pnpm 的坑、硬链接会断的坑）见
[`soul/07-bundle.json`](../soul/07-bundle.json) 的 `install` 段。
