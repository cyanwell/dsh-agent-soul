# dsh-agent-huanqi

> **换气** —— 思考预算管理器。
> 一个 agent 如果把输出预算全烧在推理里、正文一个字没出来，这一轮就是废的：
> 钱花了，事没做。这个插件负责**把它捞回来**。

---

## 它防的是什么

**「只想不做」的退化。**

长上下文 + 高 reasoning effort 下，模型会退化：
推理里开始出现低熵重复（`好。执行。好。` / `Write. / Output. / Let me write. / Go.` 这种短句轮转），
然后**停不下来** —— 预算烧光，正文空着，工具一次没调。

**它的失败形状是静默的**：你不会看到报错，你只会看到这一轮什么都没发生。

---

## 三个动作

```
① 截断      一轮的输出预算被烧光、正文与工具都是 0  →  判定这是废轮
② 再开       自动再开一轮，让它有机会真做事（最多 N 次）
③ 熔断       连开 N 次还是不行  →  停下，塞一段【能认出来的话】请人介入
```

**第 ③ 步是最重要的。** 一个自动重试机制如果只会重试，它会把钱烧在一个坏掉的循环里。
**它必须知道什么时候该喊人。**

---

## 额度：体温计，不是配额

这是整套设计里最容易做错的一处。

```
✗ 配额读法：每天 100 点，用完就没有 —— 于是 agent 开始省着用
✓ 体温计读法：额度反映【最近的状态】，正常对话慢慢攒，异常时下降，最低 1 点
```

**为什么区别很大**：配额会让 agent 把注意力放在「我还有多少」上，
而体温计只让它知道「我现在状态怎么样」。**前者改变行为，后者只提供信息。**

★ **额度在熔断时才是决定性的** —— 它决定「还值不值得再开一轮」。

## 装

```bash
dsh plugin --profile <name> add <path-to-this-package>
```

**装完要重启 DSH。**

### 默认值开箱即用

`cordis.patch.yml` 里不用配任何东西 —— 默认值就会检测「推理步骤」并在第二次时介入。

### 要调参就在 profile 层覆盖

```yaml
- set:
    - id: huanqi
      config:
        maxThinkingSteps: 3        # 连续几步只有推理、没有正文 → 判定退化
        minReasoningChars: 2048    # 推理短于这个长度不算（避免误伤正常的短思考）
        similarityThreshold: 0.8   # 相邻推理的相似度阈值 —— 低熵重复的判据
        escalate: steer            # 第二次命中时的动作：steer / cancel
        cancelCause: thinking-loop
```

**四个阈值背后各挂着一个具体的失败**，别随手改：

| 参数 | 改小了会怎样 | 改大了会怎样 |
|---|---|---|
| `maxThinkingSteps` | 正常的深度思考被打断 | 废轮多烧几轮才被发现 |
| `minReasoningChars` | 短推理被误判成退化 | 真的退化漏检 |
| `similarityThreshold` | 换个说法的正常推理被当成重复 | 重复漏检 |

---

## 它继承了两个前身

```
dsh-loop-guard            →  重复检测（推理里的低熵轮转）
dsh-reasoning-only-guard  →  空消息保护（推理没有正文）
换气                       →  把两者合成一个：检测 → 续跑 → 熔断
```

**★ 所以不要把前两个和它一起装。** 两套判据并存时，你不知道是哪一套在动手。

---

## 判据

```
✓ 它工作时应该看到：一轮被截断，紧接着自动开了一轮
✓ 熔断时应该看到：一段能认出来的话（不是沉默，不是无限重试）
✗ 不该看到：正常的深度思考被打断
```

**测试**：

```bash
node --test "test/*.spec.mjs"
```

（测试套件随源码发布；`src/` 是 TypeScript 源，`lib/` 是编译产物。）

---

## 边界

```
✗ 不判断「内容对不对」 —— 它只看形状（有没有正文、有没有工具调用、推理像不像重复）
✗ 不跨会话记账 —— 额度共享，但每一轮的判断是本地的
✗ 不替代 guard/ 家族 —— 那些管工具调用，它管【不动手】这一侧
```
