# dsh-agent-huanqi

> **换气** —— 思考预算管理器。
> 一个 agent 如果把输出预算全烧在推理里、正文一个字没出来，这一轮就是废的：
> 钱花了，事没做。这个插件负责**把它捞回来**。

---

## 它防的是什么

**「只想不做」的退化。**

长上下文 + 高 reasoning effort 下，模型会退化：
推理里开始出现低熵重复（`好。执行。好。` / `Write. / Output. / Let me write. / Go.` 这种短句轮转），
然后**停不下来** —— 预算烧光，正文空着，工具一次没调。

**它的失败形状是静默的**：你不会看到报错，你只会看到这一轮什么都没发生。

---

## 四条判据

退化不是一个形状，是**四种**。它们发生在不同的时刻，所以要挂在不同的事件上：

| # | 判据 | 挂在 | 看到的是 | 出手时机 |
|---|---|---|---|---|
| ① | **流内早杀** | `llm/stream` | 这次调用思考写了 `silentReasoningChars` 字，正文和工具还是 0 | **立刻**，不等它自己停 |
| ② | **流末判定** | `llm/stream` 结束 | 这次调用是 `reasoning-only`，而且连续停滞达到阈值 | 调用结束时 |
| ③ | **输出重复** | `llm/stream` | 同一句 / 同一个循环在正文里刷屏 | 逐块检查，发现就断流 |
| ④ | **空回合** | `session/event` | **整个回合结束了，一个字节都没吐** | `turn/end` 时 |

**为什么必须分开挂**：前三条的判断材料都在**流里** —— 它们要求「有一次模型调用，而且流里有东西可看」。
第四条的材料在**回合边界**上：`turn/end` 才知道「整个回合结束了」，而流只知道「这次调用结束了」。

一次回合可能有好几次调用。中间某次没产出是正常的（它在调工具、在读文件），
**整轮都没产出才是病**。这两件事只有 `turn/end` 分得清。

### ① 为什么必须流内

真实循环能在**一次调用里**写满 5140 个字符还不停（实测：`14:34:26` 那一步，正文 0、工具 0）。
如果只在流末判，那几分钟里没有任何人能介入。

**误报可以接受**：被误杀的这一轮本来也没产出，换气会带着「直接做」重开一轮。
**漏报的代价是整条会话卡死。** 宁可错杀。

### ④ 它从哪来

这一条 2026-10-19 从 `dsh-stalled-turn-continue` 吸收。
那个插件单独做过这件事（`turn/end` + 最后一条 assistant 消息没有 text / tool-call），
但**它自己管一套账**（`maxConsecutive: 3` + `cooldownMs: 20s`，按会话计数）。

**换气没有照搬那套账。** 空回合现在走换气自己的额度（见下一节）——
**一次续命就是一次续命，不管起因是哪种病。**

## 三个动作

```
① 截断      判定这是废轮（四条判据任一命中）
② 再开      自动再开一轮，让它有机会真做事（扣 1 点额度）
③ 熔断      额度耗尽  →  停下，塞一段【能认出来的话】请人介入
```

**第 ③ 步是最重要的。** 一个自动重试机制如果只会重试，它会把钱烧在一个坏掉的循环里。
**它必须知道什么时候该喊人。**

**四条判据共用同一段续命代码、同一本账。** 不管哪条出手：
扣同一分、用同一个上限、触发同一个熔断。**这是有意的** ——
额度是「还剩几次机会」的全局读数，不是每个判据各算各的。

---

## 第四个动作：定点清除（2026-10-31 加）

**问题**：`/compact-region` 有一条内在矛盾 —— 它要求「turn 还开着」且「摘要期间整面静止」，
而换气只能在 turn 外行动。这两个条件不能同时满足（六次尝试全败）。

**换法**：不压缩，改**做手术**。

```
① 扫最近 400 个节点，挑出「大块头」工具结果当候选（取前 12 条）
② 交给 LLM 诊断：哪几条是真污染源 —— 重复刷屏、已被后续覆盖的失败日志、
   大段重复 dump。模型必须对每条明确回 safe:true 才采纳
③ surfaceOp 直接替换那几条 tool/result 的内容 → 占位符
   （原文仍在事件日志里，用 log:session-…​#seq=N 可以回取）
```

**为什么必须给够 token**：实测诊断一次，模型思考用掉 **12808** tokens、正文只有 **880**。
预算给到 2000 时思考还没结束就被砍断，正文一个字节没有 —— 于是 `model output not parseable`。
**默认 16000**。

三条硬约束（都实测撞过）：

| 约束 | 报错 |
|---|---|
| 只能 replace surface-eligible 类型 | `session event "X" is not surface-eligible` |
| `sourceEventSeqs` 不能有重复 | `must not contain duplicates` |
| 只能改 `message.content`，不能加顶层字段 | `may change only content` |

**关掉它**：`purgeOnCuts: false` —— 完全退回老路（`/compact-region` / 全量 `/compact`）。

## 额度：体温计，不是配额

这是整套设计里最容易做错的一处。

```
✗ 配额读法：每天 100 点，用完就没有 —— 于是 agent 开始省着用
✓ 体温计读法：额度反映【最近的状态】，正常对话慢慢攒，异常时下降，最低 1 点
```

**为什么区别很大**：配额会让 agent 把注意力放在「我还有多少」上，
而体温计只让它知道「我现在状态怎么样」。**前者改变行为，后者只提供信息。**

★ **额度在熔断时才是决定性的** —— 它决定「还值不值得再开一轮」。

★ **额度是全局一份、跨会话共享的**（设计取舍：分会话管理会很麻烦）。
理由是上下文变脏通常是全局性的 —— 同一台机器、同一批模型、同样的用法。
所以一条会话把额度耗光会影响别的会话，**这是有意的**。

★ **额度只有两个入口会涨**：
- **正常轮**：这一轮产出了正文（含工具调用）、且没触发延续 —— 攒够 `normalTurnThreshold` 轮涨 1 点
- **人给**（面板上的「恢复额度」按钮）

其余时候只降。

## 装

```bash
dsh plugin --profile <name> add <path-to-this-package>
```

**装完要重启 DSH。**

### 默认值开箱即用

`cordis.patch.yml` 里不用配任何东西 —— 默认值会检测四种退化并介入。

### 要调参就在 profile 层覆盖

```yaml
- set:
    - id: huanqi
      config:
        maxContinuations: 6          # 一口气能接几次（也是额度上限）；0 = 关掉换气层，只留循环检测
        silentReasoningChars: 3000   # 流内早杀：思考写到这么多字、正文与工具仍为零，就地截断
        reasoningOnlySteps: 1        # 流末：连续几次 reasoning-only 才出手（1 = 一次就出）
        minReasoningChars: 2048      # 推理短于这个长度不计入（避免误伤短思考）
        emptyTurnContinue: true      # 空回合也续一轮（上面的判据 ④）
        anomalyWindow: 10            # 出正文后多少轮内又卡住，算一次异常（额度 −1）
        normalTurnThreshold: 6       # 攒够多少正常轮额度 +1
        warnAtCredit: 2              # 额度降到几时开始提示
```

**每个阈值背后各挂着一个具体的失败**，别随手改：

| 参数 | 改小了会怎样 | 改大了会怎样 |
|---|---|---|
| `silentReasoningChars` | 正常的长推理被误杀（实测 3000 误杀率 7.9%，8000 降到 0.37%） | 循环多烧几分钟才被发现 |
| `reasoningOnlySteps` | 单次正常的长思考就出手 | 短循环漏检 |
| `minReasoningChars` | 短推理被误判成退化 | 真的退化漏检 |
| `maxContinuations` | 机会太少，一次就熔断 | 坏循环多烧几轮 |
| `emptyTurnContinue` | 关掉 → 空回合没人管，会话停在那儿等人手打「继续」 | —— |

★ **`silentReasoningChars` 那条是实测来的**：3000 会误杀约 7.9% 的正常长推理
（全量 7533 步里，3000 字以上的正常步共 592 个），2026-10-12 当晚实测被误截断 4 次、全是正常思考。
**真正的主力是流末那层**（`reasoning-only` + `stalledRun >= reasoningOnlySteps`）——
全史 4 次循环全中、正常步零误报；流内这层只负责「别等它自己停」。

## 它继承了两个前身

```
dsh-loop-guard               →  重复检测（推理里的低熵轮转）
dsh-reasoning-only-guard     →  空消息保护（推理没有正文）
dsh-stalled-turn-continue    →  空回合续跑（turn/end 时一个字节都没有）
换气                          →  把三者合成一个：四条判据 → 续跑 → 熔断
```

**★ 所以不要把它们和换气一起装。** 两套判据并存时，你不知道是哪一套在动手，
而且**两套账会各扣各的** —— 一轮被续成两轮。

`dsh-stalled-turn-continue` 的 `maxConsecutive: 3` 现在已经由换气的额度接管：
**额度耗尽就是「不再接了」**，不需要第二个计数器。

## 判据

```
✓ 它工作时应该看到：一轮被截断，紧接着自动开了一轮，额度 −1
✓ 空回合时应该看到：回合结束后自动开了一轮
✓ 熔断时应该看到：一段能认出来的话（不是沉默，不是无限重试）
✗ 不该看到：正常的深度思考被打断
✗ 不该看到：同一轮被续两次（那是两套判据同时在动）
```

```bash
node --test "test/*.spec.mjs"
```

## 边界

```
✗ 不判断「内容对不对」 —— 它只看形状（有没有正文、有没有工具调用、推理像不像重复）
✗ 不判「产出的质量」 —— 写出一堆垃圾也算「有产出」，换气看不见这一层
    （它只能看出「一个字节都没有」，看不出「写的东西没用」。这是已知的盲区）
✗ 不替代 guard/ 家族 —— 那些管工具调用，它管【不动手】这一侧
```

## 更新记录

### 1.2.0 — 2026-10-31 · 截断压缩改走 LLM 诊断 + 定点清除

**为什么改**：`/compact-region` 有一条内在矛盾 —— 它要求「turn 还开着」且「摘要期间整面静止」，
而换气只能在 turn 外行动。两个条件不能同时满足，六次尝试全败。

**改了什么**：`mode === 'region'` 时不再碰 `compactRegion`，改用 `surfaceOp` 直接替换
`tool/result` 的内容 —— 不需要 open turn。

1. 扫最近 400 个节点，挑出超过 `purgeMaxChars` 的工具结果当候选（取最长的前 12 条）
2. 交给 LLM 诊断：哪几条是真污染源（重复刷屏 / 已被后续覆盖的失败日志 / 大段 dump）。
   模型必须对每条明确回 `safe: true` 才采纳；编造的 seq 一律丢弃；最多 3 条
3. `surfaceOp` 替换成占位符。**原文仍在事件日志里**，用 `log:session-…#seq=N` 可以回取

候选为空、LLM 失败、或全部替换失败 → 落回原来的全量路径，不会卡住。

**怎么验的**：`_plugin-diag.log` 里连续两次触发，日志依次出现

```
LLM 诊断 ok=true 采纳=3 扫描=71  diag=n=2[reasoning:12808,text:880]
OK 28857 新seq=29042 / OK 28866 新seq=29043 / OK 28936 新seq=29044
清除 3/3 条
compactOnce(region) → OK range=null
```

第二次触发的候选列表里，上一轮清掉的三个 seq **全部消失** —— 这是可 поверхности替换真的生效的证据
（不是「调用成功」，是「可见面变了」）。

**踩到的坑（值得记下来）**：`maxTokens` 原来给 2000，模型思考就吃掉 12808 tokens、
正文只有 880。于是思考还没结束就被砍断，正文一个字节没有 → 报 `model output not parseable`。
**默认提到 16000**。这条不是猜的，是从 `diag=n=2[reasoning:...]` 里读出来的。

顺带重写了解析器（四层退让：直解析 / 剥 md 围栏 / 括号配平跳过字符串 / 截断抢救），
三层都要求 `items` 是数组 —— 修掉了「截断时把单个 item 当结果返回」那个 bug。

**新增配置**：`purgeOnCuts`（默认 true）/ `purgeMaxItems`（默认 3）/ `purgeMaxChars`（默认 20000）。
关掉 `purgeOnCuts` 就完全退回老路。

**还有一个账要还**：这套 purge 此前只存在于 `lib/index.js` 产物里，`src/index.ts` 一行都没有
—— 跑一次 `tsc` 就全没了。本次已把 307 行补进源码，`tsc --noEmit` 零错误。
