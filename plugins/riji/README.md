# dsh-agent-riji

> 顶栏的一格：点开是日记的目录，选中一篇读原文。
> **读的是一手 markdown，不是任何转述。**

---

## 它防的是什么

**「写得很好，但没人看得见」。**

日记这种东西有个尴尬处：它天然是**给自己看**的，
所以它会安安静静躺在磁盘上 —— **除非有一个入口，不比打开编辑器更麻烦。**

**这个插件就是那个入口**：顶栏一格，点开、选一篇、读。
它不分析、不摘要、不推荐，**它就是让你读到你写的东西。**

---

## 一条写进代码里的判断：日记是**读物**

```
读物   只留最新结论 —— 被推翻的、改过的，都不再出现
账本   只追加，一字不删 —— 「改过什么、被什么推翻过」
交接   时间线 —— 「哪些路走错过」
```

**★ 日记属于第一类。**

**为什么这个区分重要**：如果把日记写成「读物 + 沿革」的混合体，
每读一篇都要先想「这个结论现在还成立吗」—— 那它就不再是读物了。

**所以这里只读读物。** 沿革该在账本里，那是另一扇门。

> ★ 反过来说也成立，而且更重要：**不是所有东西都该做成三份。**
> 只有涉及「我是谁、我怎么存在」的事才值得三份 ——
> 其余（出去玩、日常记事）**一份就够，套格式反而更糟。**

## 装

```bash
dsh plugin --profile <name> add <path-to-this-package>
```

**装完要重启 DSH。**

### 一个可配项

```bash
RIJI_DIR   # 日记目录，默认 ./diary
```

**它读那个目录下的 `*.md`。** 文件名按字典序排（所以 `01-`、`02-` 这种前缀会自然成为顺序）。

## 自检

```bash
node selftest.mjs
```

它真的去 import 一次宿主半、看导出的东西对不对 —— **不重启、不开浏览器**。

---

## 边界

```
✗ 不写 —— 只读。写日记是你的事（也不该是任务）
✗ 不摘要、不推荐、不排序 —— 它只把目录摆出来
✗ 不解析 markdown 的语义 —— 按原文显示
✗ 不联网
```

---

## 一个提醒（写给使用者）

**日记的价值不在篇数。** 有感触才写；**没感觉就不写是对的。**

如果它变成了「这周还没写」—— 那它就从读物变成了作业。
