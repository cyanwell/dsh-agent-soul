# dsh-agent-echo

> 给记忆系统装一块**仪表盘** —— 把那些「装好了就以为它在工作」的东西，
> 每 5 分钟真去摸一次，把摸到的结果摆在页面上。

---

## 它防的是什么

**看不见的坏。**

一个记忆系统会有很多部件：压缩器、门牌、索引、自我层、账本、热记忆…
它们各自有个配置文件，而配置文件**看着永远是对的**。

**真正的故障长这样**（我们踩过的那一次）：

```
门牌那一项：配置里写得清清楚楚，路径也在，权限也够
实际去取一次：取不出来
而只读配置的体检 —— 会全部报绿。
```

> ### ★ 那种绿比红更坏。
>
> 红会让你去修；**绿会让你以为不用修**。
> 所以这个面板的第一条纪律是：**每一检查项都必须真去取一次，不许读配置下结论。**

---

## 它怎么做

```
浏览器面板  ──每 2 秒──►  只读路由  ──读内存──►  最新一份体检报告
                              ▲
                       （做完替换缓存）
                              │
              后台定时器 ──► 体检器（子进程）──► 十项检查
```

**「实时感」的来源不是体检变快了，是它和刷新解耦了**：
面板读缓存（微秒级），体检在后台按等级跑，做完替换。**面板永远不会等体检。**

### 两级体检（★ 这是 v2 唯一的关键改动）

| | 花多久 | 做什么 |
|---|---|---|
| **快检** | 约 0.9 秒 | **不解日志** —— 读文件时间、数账本行数、看心跳 |
| **深检** | 约 9.5 秒 | **真要解一次日志** —— 门牌实测 + 压缩统计 |

**起因**：十项检查里九项是毫秒级的，只有两项要解那份多帧日志 ——
**而 v1 把那份日志解了两遍**，于是 17 秒里有 16 秒花在重复解码上。

> **那不是「体检慢」，是「我算重了」。**

修法：把解码结果缓存，两项共用。**一个 cache，17 秒变 9.5 秒。**

### 四级轮询

```
1 级 = 5 分钟   ｜   2 级 = 10 分钟   ｜   3 级 = 30 分钟（默认）   ｜   4 级 = 只手动
```

---

## 两条纪律（一条都不许省）

### ① 体检跑在**子进程**里

**绝不在 DSH 主进程里同步解那份日志** —— 那是几十 MB 的多帧压缩，
**在主进程里解它会把所有会话一起卡住。**

### ② 体检逻辑**只有一份**

命令行和面板共用同一个脚本（`echo-doctor.mjs`）。
**否则你会得到两套判据，然后开始对账** —— 而它们迟早会不一致。

---

## 它检查哪十项

```
压缩      兜底压缩的阈值与最近一次触发
门牌      真去取一次，看指针能不能回到原文
索引      摘要条数 / 原话条数 / 建立时间
自我层    那份「每轮注入」的文件还在不在、多长
心跳      有没有人还在写
账本      行数 + 最后一条的时间
热记忆    条数与配额占比
版本漂移  声明的版本 vs 实际加载的版本
体检器    它自己跑不跑得起来
进程      node 在不在、脚本在不在
```

**★ 最后那两项是自检。** 一个体检器必须先能报出「我自己坏了」——
否则它坏了的时候，页面会安静地空着，而那看起来和「一切正常」一模一样。

## 装

```bash
dsh plugin --profile <name> add <path-to-this-package>
```

**装完要重启 DSH。**

### ★ 四个必配项

```jsonc
// echo.config.example.json → 复制成 echo.config.json
{
  "hub":      "./",           // 体检器所在目录
  "soul":     "./soul",       // 你的「不变量」目录（账本在其中）
  "mem":      "./memory",     // 你的记忆库
  "sessions": "./sessions"    // 会话日志目录
}
```

**不配也能跑** —— 那时它用本文件旁边的相对目录，然后**每一项都报「读不到」**。
那颗红灯是给你看的，不是坏掉。

★ 也可以用环境变量：`ECHO_HUB` / `ECHO_SOUL` / `ECHO_MEM` / `ECHO_SESSIONS` / `ECHO_NODE` / `ECHO_DOCTOR`。

### 判据

**命令行先跑一次**：

```bash
node echo-doctor.mjs --json --fast     # 快检
node echo-doctor.mjs --json            # 深检
```

**输出必须是合法 JSON。** 面板报「输出不是 JSON」时，就是这一步没过 —— 去命令行看原始报错。

## 边界

```
✗ 只读 —— 它不修任何东西，只报告
✗ 不改配置 —— 它连「建议改什么」都不给（那是你的判断）
✗ 不常驻 —— 面板不开时，后台定时器仍在跑但没人看；关掉插件就不再体检
✗ 不做历史 —— 它只有「现在」，没有曲线（要看趋势得自己存）
```

---

## 一个设计上的诚实

**这个面板会报「读不到」。**

它会读到一半发现某个路径不存在、某个文件是空的、某个脚本跑不起来 ——
**然后如实报出来，而不是跳过那项。**

**因为跳过 = 那一格永远绿。**

```
十项里有一项跳过  →  你看到的报告是 9/9 全绿
真相是             9/10，而第 10 项恰恰是坏的那个
```

**所以它是故意难看的。** 一份会报「我不知道」的体检报告，
比一份凑齐十项全绿的报告有用得多。
