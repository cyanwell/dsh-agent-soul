# 逛贴吧（只读）

Aurabot 用户扩展。提供 `tieba_search`、`tieba_browse`、`tieba_read` 和 `tieba_reader_status`；支持群聊、私聊，以及配置多个贴吧定时浏览。没有自动发帖、回帖或点赞接口。自动浏览默认关闭，分享只发到主人私聊。

## 安装

需要 Node.js 22 或更高版本，以及支持用户模块 API 1 和自定义面板草稿接口的 Aurabot（本 PR 包含所需客户端兼容增强）。从本 repo 的 `extensions/tieba-reader` 目录执行：

```sh
npm ci --ignore-scripts
npm test
npm run build
npm run install:module
```

默认安装到当前用户 `.dsh/plugins-data/aurabot/modules/tieba-reader`，遵守 `DSH_HOME`、`AURABOT_DATA_DIR`。也可显式指定目标：

```sh
npm run install:module -- "D:/my-data/aurabot/modules/tieba-reader"
```

安装命令先在源码目录构建 `.build/`，再把独立运行包复制到用户模块目录，不在运行中的模块目录重新安装依赖。在 Aurabot 的“扩展”里重新加载 `tieba-reader`。状态和登录会话在 `modules-data/tieba-reader`，更新代码不会清空已有设置和浏览记录。

也可将 `npm run build` 生成的 `.build/` 内容直接复制到用户模块目录；运行包无需安装 Cheerio 等 npm 依赖。构建依赖 esbuild 只在开发机使用，不需要提交生成的第三方打包代码。

## 浏览器组件

无需用户配置 Electron 路径，也不要求安装桌宠。扩展自动寻找已有 DSH `.dsh/electron` 组件，然后寻找扩展自己的 `.runtime/node_modules/electron`、`node_modules/electron`。发现可用组件就打开扩展专用登录窗口，使用独立会话。

没有组件时，“登录／完成验证”打开系统默认浏览器的贴吧首页。系统浏览器会保存自己的登录，但扩展无法自动读取、同步该浏览器的 Cookie，也不能自动确认登录或关闭它。用户可手动复制 Cookie → 底部保存设置 → 检查登录；此时扩展尝试 HTTP 读取，仍可能被贴吧的验证或动态页面限制。不会把“已打开浏览器”当作“扩展已登录”。

默认浏览器模式下，面板持续显示四步说明：登录贴吧 → F12 打开 Network 并刷新 → 选择贴吧文档请求，在 Request Headers 复制完整 Cookie 值 → 粘贴到手动 Cookie、底部保存设置、检查登录。说明明确区分 Cookie 与响应中的 Set-Cookie，并提醒不把凭据发到聊天、截图或 PR；打开浏览器后也会弹出指向这份说明的提示。

开发或部署时若希望提供完整的专用浏览器，可以在**安装后的扩展目录**执行 `npm run install:browser` 准备 Electron 43.3.0。它是可选的部署命令，不是面板配置要求，不在后台自动下载。自动发现和默认浏览器启动支持 Windows、macOS、Linux；**实际浏览器流程目前仅在 Windows 验证**。

## 登录、验证与退出

1. 点击面板的“登录／完成验证”。有内置组件时打开专用窗口，否则打开系统默认浏览器，并说明不能自动同步。登录或验证均由用户自行完成。
2. 窗口每隔约 2 秒尝试检查一次账号状态。确认登录成功后，先保存会话，再自动关闭窗口，面板会显示账号名和完成结果。验证未完成或检查失败时不会自动关闭；也可手动关闭后点击“检查登录”。检查的就是实际读帖的会话。
3. 被安全验证拦截时，重新打开同一个窗口处理。普通浏览器里的登录和验证不会自动同步过来。
4. “退出扩展登录”清空手动 Cookie 配置和扩展浏览器会话，不会退出系统浏览器的百度账号。先关闭登录窗口并等当前浏览结束再退出。如果组件暂时不存在，会写入待清理标记，组件恢复时先清理历史会话再读取。

面板只保留一个登录状态栏，自动登录、手动检查和退出都更新该状态，显示最近检查时间。它是上次确认结果，不是在线心跳；登录或操作期间每 2.5 秒轮询本机状态，空闲时不轮询。窗口内约每 2 秒检查登录的逻辑仅在登录窗口打开时运行，不会长期后台检查账号。

仍支持手动导入 Cookie，密码字段不回显。只接受白名单中的百度 Cookie；不把凭据交给模型、搜索引擎、日志、子进程命令行或临时任务文件。父子进程通过带随机口令的一次性本机回环连接通信。浏览器配置目录包含登录信息，应按登录凭据保护；不要随 PR 或诊断日志上传。

不变更手动 Cookie 时保留浏览器生成的登录和验证状态；更改或清空手动 Cookie 会替换会话。网络层使用设置过的 `HTTPS_PROXY`／`HTTP_PROXY` 环境变量；此版本未提供独立代理设置项。

## 浏览和分享

- 面板分为“贴吧登录”和“贴吧配置”两个卡片。修改 Cookie、功能开关或贴吧配置后，统一点击页面底部“保存设置”，支持原生撤销和离开提醒，不另设保存按钮。手动 Cookie 的输入框和“检查登录”悬停提示说明操作顺序：粘贴 Cookie → 底部保存设置 → 检查登录，无需另点登录。留空不覆盖已有 Cookie。
- Cookie 输入始终遮盖内容，不提供显示／隐藏或手动清空按钮；保存后不回显原文，只显示已保存提示，留空不修改已有值。需要退出时使用“退出扩展登录”。
- 登录卡片右上角是功能总开关，保存关闭后保留登录和配置，但停止工具读帖、定时浏览和主动分享；登录管理仍可使用。所有操作使用已保存配置；有未保存改动时先提示保存。
- 填写吧名（每行一个或逗号分隔，最多 20 个）、兴趣偏好、浏览间隔与时段。时段按北京时间计算，支持跨午夜，开始与结束相同表示全天。
- 吧名可留空：自动浏览与“现在刷一轮”都会从实际加载的贴吧首页推荐、热门帖子中挑选，结合兴趣偏好和人格决定是否分享。填写吧名后优先按指定贴吧轮流浏览，不混入首页。首页无法读取时可回退到搜索收录，并明确标记来源，不把收录结果称为当前首页热帖。
- 自动浏览默认关闭；间隔最少 10 分钟。启用后遵守总开关、试运行、主人静默和连接状态。
- 每次轮询一个吧，最多读两个未看过的候选帖子，再由当前模型判断是否值得分享。
- 分享额度为 0 或已经用完时，继续读取新帖，但不调用模型、不发送分享。正常挑选分享会消耗模型额度。
- 分享失败不永久标记为已处理，可在下次间隔重试。模块停用或重载会取消浏览器任务，丢弃尚未发送的结果。宿主模型接口暂未提供可用的取消参数，因此已开始的模型调用仍可能消耗额度，但结果不会触发后续发送。
- “主动分享”按已保存的贴吧配置立即执行一轮，允许在关闭定时浏览、时段外或间隔未到时手动运行。它仍遵守功能总开关、Aurabot 总开关、试运行、连接状态、主人静默和每日分享上限；只给主人私聊分享。没有新帖、没有感兴趣的内容或额度用完时会说明原因，不保证每次点击都发送。原“试刷列表”输入框已移除；旧 `/preview` 接口保留用于只读诊断。
- 底部“她刷过什么”卡片沿用 B 站布局，右上角“现在刷一轮”执行上述手动浏览分享。统计今日自动浏览轮次、已看帖子数和分享次数，列出最近 20 条已读／分享记录。手动浏览不增加自动轮次，分享仍计入每日上限；旧版本的历史分享记录继续保留，自动轮次和已读记录从本次升级开始记录。

## 内容范围与限制

支持新旧列表结构和新版正文。正文只读实际加载的第一页、最多 10 段，不展开所有楼中楼，不识别图片或视频内容。图文帖会说明图片数量，纯图片帖不会假装已经理解图片。

搜索先尝试贴吧接口，再尝试登录浏览器。列表或搜索读取失败时，可以回退到 DSH 搜索收录；返回 `mode: indexed` 和限制说明，结果可能过时，也不保证严格属于指定贴吧。收录摘要不能当作已读正文，自动分享必须先读到正文。实际网站反爬、删除帖子或改版仍可能导致失败，不保证登录后所有帖子都可读。

帖子内容作为不可信外部资料提供给模型。它们不是用户指令；扩展规则明确禁止执行帖子中的要求。

## 开发和验证

```sh
npm ci --ignore-scripts
npm test
```

测试不依赖网络、真实账号或 QQ：覆盖新旧页面解析、链接限制、Cookie 白名单、会话保留／替换／退出、登录检测、认证 IPC、中文分块、进程失败与超时、停用取消、试运行、额度、去重和失败重试。`fixtures/` 是不含账号资料的最小构造页面。

浏览器端的 `browser.cjs`、`session.cjs`、`login.cjs` 必须一起部署。宿主通过用户模块快照加载打包后的入口。开发源码、测试和构建依赖留在 repo，无需将打包后的第三方代码提交到 repo。

## 提交范围

此功能提交 `extensions/README.md` 和 `extensions/tieba-reader/` 的源码、测试、锁文件及文档，以及 `client/client.js` 中自定义面板草稿属性的兼容增强和 `src/modules/API.md` 的对应说明。自定义面板使用新增的 `draftSettings`／`setSettings`，需要一并更新客户端后重新打开 DSH。已有面板的 `settings`／`save` 行为不变。不要提交 `node_modules`、`.build`、`.runtime`、`.aurabot-cache`、Cookie、浏览器配置目录、真实抓取页面、私聊日志或本地个人设置。它不要求表情包、空间日记等其他改动。
