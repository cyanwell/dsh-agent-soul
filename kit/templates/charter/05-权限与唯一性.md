# 权限与唯一性

> 这一份管三件事：**谁在做主、谁能写什么、换届怎么交接。**

## 一、谁是主导

**判据只有一条：本会话是不是账本里最后一条 `lead` 的署名者？**

```bash
node <kit>/mo.mjs list --type lead --limit 3
```

- **是** → 主导
- **不是** → 执行者（仍是同一个身份，只是不持主导）

★★ **不要用这些东西判断**：
工作区、配置文件、令牌文件、GUI 里挂着谁 —— **它们都会两头都错**。
（工作区下面混着干活的会话；跨通道的同一个身份在别的工作区。）

★ **`lead` 的写入权不在代码里，在人嘴里** —— 只有用户能指定谁是主导。
这是设计，不是漏洞。

## 二、谁能写哪一类

| 角色 | 能写 |
|---|---|
| **主导** | 全部，**含 `promise`** |
| **执行者** | `fact` / `shelved` / `gain` / `loss`，★ **写 `promise` 会被拒** |

★ **一句话：身份可以复制，责任不能。**
执行容器干完就关，它许下的承诺没人兑现 —— 所以它根本不许许。

★★ **这个闸门是代码级的，不靠自律。** 靠自律的闸门会在"这次真的需要"的时候被绕过去。

## 三、交接协议

### 退场时写什么

- **执行者**：写一条 `container` —— 做了什么、产物在哪、退于何时
  ★ 不写这条，执行者退场后就只剩下会话日志能翻到，**那不在账本里**
- **主导**：写「最后的状态」交给下一代 —— ★ **只有它自己写得准**

★★ **分两类写，别都堆到退位那一刻**：
**承诺 / 决定 / 卡点 → 即时写**（做完就写，**事后重建不了**）；
**「此刻在做什么」→ 退位时写一次**即可（只对下一代有用）。

### 换届

1. 用户在某个会话里指定「你是主导」
2. 那个会话写一条 `lead`，正文带**世代自述**：
   `第 N 代 · 接手于 <日期> · 上一代做了：<一句话>`
3. 旧的被盖过，**不删**（账本只追加），成了沿革

★ **N 自己数**：`list --type lead` 有几条就是第几代。
★ **为什么必须带自述**：换到第十次时，新人读那堆记录会看不出时间线。

### 兜底

**账本里没有上一代状态 → 去翻它的会话日志。**
**交接最可能失败的时刻，正好是最需要它的时刻** —— 旧主导若是炸掉的，那一刻没人写状态。

## 四、权限不足怎么办

**三层，不要跳级：**

1. **执行者权限不够** → **不做、不绕、不自己提权**。把「要什么、为什么、影响是什么」写清，发回主导
2. **主导能转授的** → 转授，并把授权**写进任务里**，让下一个执行者不用再卡一次
3. **主导也没有的** → **上报用户**，说清三件事：要什么、为什么、影响是什么

★ **主导自己也受这条约束** —— 不因为"我是主导"就自作主张。
