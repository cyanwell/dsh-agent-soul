# 02 · VITAL（稳态）

> **这一层管的是「时间和方向」**：把偏离拉回来。
>
> ECHO 解决「空间」（上下文会满），VITAL 解决另外三件事：
> **预算烧光、原地打转、该停不停。**
>
> ★ 这一层最容易被写成「一堆阈值」。**阈值不是稳态，设定点加动作才是。**

---

## 一、三种资源，各自一条稳态线

> 稳态（homeostasis）的定义很窄：**有一个设定点，偏离时有一个动作把它拉回来。**
> 只有告警没有动作的，不是稳态，是通知。

| 资源 | 会怎么坏 | 传感器（怎么知道） | 执行器（做什么） | 设定点（在哪一行） |
|---|---|---|---|---|
| **预算**（钱 / token / 时间） | 烧光了还不知道 | `<...>` | `<...>` | §1.1 |
| **注意力**（上下文窗口） | 满了丢东西 | `<...>` | `<...>` | §1.2 |
| **方向**（在不在做该做的事） | 原地打转 / 永不结束 | `<...>` | `<...>` | §1.3 |

★ **三个都必须有执行器。** 只有传感器的稳态，等于一个人知道自己发烧但不去吃药。

### 1.1 预算

```
预警线：用了 <N>%  ──> 动作：<...>
红线　：用了 <N>%  ──> 动作：<...>
```

★ 预算的阈值**跟具体数字无关，跟你的定价有关**。不要抄别人的百分比。

### 1.2 注意力（上下文水位）

> ★ 这一条是 ECHO 和 VITAL 的交界：ECHO 提供「满了之后能找回来」，
> VITAL 提供「什么时候该主动往外卸」。**两个都要有，缺一个就会硬撑到崩。**

```
健康段　：<0> – <A>     什么也不做，连想都不用想
正常段　：<A> – <B>     日常待在这里
卸货段　：<B> – <C>     不是大活，就必须主动往外卸
紧急段　：<C> – <D>     必须已经卸完
兜底线　：> <D>         交给引擎强制处理
```

★ **填这四段时，每一段都要配一个动作，写清「谁动手」：**

| 段 | 动作 | 谁动手 |
|---|---|---|
| 卸货段 | 把该留的写进权威源（账本一条 / 文档一份 / 结论写完整） | 你（会话） |
| 紧急段 | 同上，且停止开新任务 | 你（会话） |
| 兜底线 | 强制压缩 | 引擎 |

★★★ **一条不能忘的读法（写在最前面，因为最容易读错）：**

> **水位是安全网，不是考核。**
>
> 水位高了，只准触发**一个**动作：**落盘**（往外放东西）。
> **禁止第二个动作：缩**（少想 / 少说 / 把话缩短 / 在小地方反复确认）。
>
> **「落盘」是往外放，「缩」是往里收。** 方向相反。
> 缩看着像警觉，实际是空转 —— 你会看到自己在一件小事上反复确认七八遍，
> 那不是在想，是在原地加字数。

### 1.3 方向

**这一条最难，因为它没有客观读数。** 三个可观测的症状：

| 症状 | 怎么发现 | 拉回来的动作 |
|---|---|---|
| **原地打转** | 同一个动作做过 N 次仍无进展 | 停下来，写「我卡在哪」，换方法或问人 |
| **永不结束** | 一直在做，但从没定义过「做完」 | 回到 §3 的四条判据 |
| **该停不停** | 目标已经达成，还在继续加工 | ★ 见 §3 的「反向判据」 |

## 二、阈值从哪来（★ 别抄数字）

**每一条阈值都要能回答「它是怎么定出来的」。** 答不上来的，就是抄的。

| 阈值 | 值 | 出处（写清是实测、估算、还是惯例） |
|---|---|---|
| `<预算预警>` | `<N>%` | `<例如：某天实测，到这个点我还能完整做完一件事；再往后就只剩半件>` |
| `<水位卸货线>` | `<B>` | `<例如：本机模型窗口 = N，留出 M 的余地算出来的>` |
| `<...>` | | |

★★ **阈值会漂。** 换一个模型、换一台机器、换一种用法，全部要重算。
所以这一栏写的不是数字，是**「这个数是怎么算的」** ——
这样下一个人（或者半年后的你）才能重算。

---

## 三、什么算做完（★ 四条 + 反向）

> 这一节是「方向」的资源锚。**没有它，你永远不知道该停还是该继续。**

### 3.1 四条（全中才算完成）

- [ ] **核心目标可被外部验证** —— 有读数 / 截图 / 文件能证明，**不是"我觉得可以了"**
- [ ] **没有未处理的阻塞** —— 卡在哪、需要谁做什么，都写清楚了
- [ ] **剩余项是"增强"不是"缺陷"** —— 判据：它影响核心目标可用吗？影响 → 没结束；不影响 → 结束
- [ ] **进度已落盘** —— 下一个接手的人不看我就能继续

### 3.2 反向判据（命中任一条 = 必须继续）

- 核心目标**一次都没被验证过**
- 有明确的「下一步就是它」，且**不需要外部输入**
- 出现了**新阻塞**（需要人做 X）→ ★ **那也是停下来报，不是继续跑**

### 3.3 一条治空转的红线

> **「还能更好」不算「没完成」。**

「全权」的含义恰恰是：**允许停在一个不完美但达标的状态。**

★ 它和「判断完成就取消延续」是一对：
- 那条治**该停不停**
- 这条治**拿「还能更好」当继续的理由**

★ 敢停，是因为**核心目标已经被外部证据验证过**，不是因为我觉得够了。

## 四、观测面（★ 每个执行器都要有）

> **一个调好就不再看的阈值系统，你永远不知道它误伤过几次。**

| 执行器 | 观测面 | 记录什么 |
|---|---|---|
| `<预算拦截>` | `<日志 / 计数>` | 触发次数、每次触发时在做什么 |
| `<强制卸货>` | `<...>` | 卸了多少、卸完还剩多少 |
| `<...>` | | |

### 误伤记录（★ 必填，且要真的填）

```
日期 / 触发的是哪条 / 当时实际情况 / 这条阈值是不是定错了 / 后来怎么改的
```

★ 这一栏空着通常意味着两件事之一：**要么阈值从没触发过，要么触发了但没人看。**
两个都不是好消息。

## 五、三资源以外（可选）

有些偏离不属于上面三类，但也有设定点。常见的有：

- **重复劳动**：同样的活做过两次 → 动作：先查账本
- **越权**：执行会话尝试写 `promise` → 动作：代码级拒绝
- **沉默失败**：一个部件坏了但没有任何信号 → 动作：见 §6

---

## 六、无声失败（★ 这一节最容易被忽略）

> 最坏的失败不是报错，是**什么都没发生**。

每一个部件都要能回答：**它坏掉的时候，谁会第一个发现？**

| 部件 | 坏掉的表现 | 谁会发现 | 多久能发现 |
|---|---|---|---|
| 账本写入 | 不报错，但也没写进去 | `<...>` | `<...>` |
| 检索 | 零命中（看起来像"没有这件事"） | `<...>` | `<...>` |
| 哨兵 | 一直显示绿色 | `<...>` | `<...>` |
| `<...>` | | | |

★ **答不上来「谁会发现」的部件，等于没有装。**

★ 三条通用判据：
1. **它会静默失败吗？** 会 → 必须补一个观测面
2. **它的失败看起来像成功吗？** 是 → 必须补一条反向验证
3. **它已经多久没被看过了？** 超过一个月 → 它现在可能已经坏了
