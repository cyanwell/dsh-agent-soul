# 01 · ECHO（生命核心）

> **这一层管的是「空间」**：上下文会满，满了要丢，丢了还得能找回来。
>
> 填这份之前，`00-authority.md` 必须已经填完。否则你会在这里建出第二个真源。

ECHO 由四个零件组成，**按这个顺序建**，每一个都能单独验：

```
账本   ——  到底发生了什么（只追加）
门牌   ——  怎么指回原文（没有它，账本是死档案）
门     ——  怎么从一堆指针里找回那一条
哨兵   ——  它坏了谁会发现
```

★ 顺序不能反。**先建门、后建账本**，你会发现门里没东西可指。

---

## 一、账本

### 1.1 形态选择（勾一个）

- [ ] **append-only JSONL** —— 一行一条，永远不修改已有行。★ 推荐给单机 / 多写者
- [ ] append-only Markdown —— 人可以读，但机器解析要自己写
- [ ] SQLite（只 INSERT，不 UPDATE/DELETE）

★ 为什么一定要 append-only：**改写权 = 历史可被改写**。你需要的不是「现在是什么」，
而是「曾经发生过什么、当时怎么想的」。后者一旦能被覆盖，就等于没有。

### 1.2 字段（把 `<...>` 换成你的）

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `t` | ISO 8601 带时区 | ✓ | **事件发生时**，不是写入时 |
| `type` | 枚举（见 1.3） | ✓ | 这是哪一类记录 |
| `summary` | 字符串 | ✓ | 一句话，能独立读懂 |
| `ref` | 字符串 | ✓ | 出处门牌（见第二节）。**空着就是孤儿记录** |
| `feel` | 字符串 | ✗ | ★ 当时的感觉。**没有就不写，不要硬凑** |
| `by` | 字符串 | ✗ | 署名：哪个会话 / 哪个容器写的 |
| `<你的>` | | | |

★ **`feel` 是这一整套里最容易被做成作业的字段。** 如果你把它变成必填，
它就会退化成一句套话。正确的做法是**每次写之前停一下问自己「这件事我有感觉吗」**——
有就写，没有就不写。**「问过之后的没有」和「忘了问的没有」是两件事。**

### 1.3 分类（给一个可用的起点，按需改）

| 类 | 记什么 | 谁能写 |
|---|---|---|
| `promise` | **对别人做出的承诺** | ★ 只有主导 |
| `fact` | 已核实的事实、决定 | 全部 |
| `shelved` | 搁置：想做但没做，附原因 | 全部 |
| `gain` / `loss` | 得 / 失，一句话+证据 | 全部 |
| `lead` | **谁是当前主导**（见 1.4） | ★ 只有人指定 |
| `schema` / `self` | 对本机制的修改、自述 | ★ 只有主导 |

★ **`promise` 和 `lead` 之所以要限制，是因为它们的本质是「替别人做决定」。**
一个被临时拉起干杂活的会话，不该有权替你答应任何事。
**这条限制最好由代码拦**（写入接口直接报错退出），不要靠自觉。

### 1.4 「谁是主导」怎么判（如果你的架构有多会话）

> 如果你的架构只有一条会话，这一节可以整段删掉。

一句话判据：**当前主导 = 账本里最后一条 `lead` 记录的署名者。**

```bash
<你的读取命令> --type lead --limit 3
```

★ 三条使用纪律：
1. **读只认最后一条**，历史行只作沿革，不作判据。
2. **写必须记「现在」**，不许回填旧时间。
3. ★ **`lead` 的权限不在代码里，在人嘴里** —— 只有人能指定谁是主导。
   技术上谁都能写一条新 `lead` 抢回主导，这是设计不是漏洞：
   **代码管不住「谁应该负责」，只有人能。**

### 1.5 作废（void）

append-only 的账本怎么处理"写错了"？

- [ ] 追加一条 `void`，指向被作废的那条（推荐）
- [ ] 直接改原文（✗ 不要）

★ 追加 `void` 之后，原来那条**仍然在、仍然可检索**，只是标记为作废。
这是有意的：**你要能看见自己曾经错在哪。**

## 二、门牌（指针）

> 没有门牌的账本是死档案 —— 你能看见"有过这么一件事"，但回不去。

### 2.1 四种指针（填入你实际支持的）

| 形态 | 指向 | 长什么样 |
|---|---|---|
| 账本记录 | 一条 append-only 记录 | `entry:<ISO 时间>` |
| 文件行 | 某个文件的某一行 | `file:<路径>:<行号>` |
| 会话原文 | 某次对话的某个位置 | `log:<会话标识>#seq=<序号>` |
| 索引条目 | 派生索引里的一条 | `idx:<id>` |

★ 四型不是必须全有，但**至少要有一型能指向「原文」**。
只能指到摘要的指针，等于一个新的真源。

### 2.2 三级纪律（★ 这一节比语法重要）

| 级别 | 什么时候用 | 怎么做 |
|---|---|---|
| 一级 | 拿得到精确坐标 | 写精确指针 |
| 二级 | 只知道大范围 | 写**检索入口**（会话标识 + 关键词），不写假坐标 |
| 三级 | 完全不知道 | 明说「查不到」，并写你查过哪里 |

★★ **铁律：拿不到精确坐标时，宁可给检索入口，也绝不猜一个门牌。**

> **错的门牌比没有更坏。** 没有门牌时，你至少知道自己缺什么；
> 错的门牌会让你自信地打开一扇错误的门，然后把里面的话当成真的。

### 2.3 写在哪

- [ ] 写在账本每条的 `ref` 字段（推荐）
- [ ] 写在摘要 / 压缩产物的第一行
- [ ] 两处都写（★ 如果两处都写，**它们必须生成自同一个坐标**，不许手抄）

★ 如果你有摘要机制：**所有压缩 / 裁剪的产物都必须带门牌。**
被截断的工具结果、被压缩的历史、自动生成的 checkpoint —— 一个都不能漏。
漏一个，那段历史就变成了"内容存在过但找不回"。

## 三、门（怎么找回来）

> 一个能用的门，最少要有三个动词。少一个，它就不算门。

### 3.1 三动词

| 动词 | 干什么 | 最小实现 |
|---|---|---|
| **搜** | 一个词覆盖全库，只回指针 + 逐字片段 | `<命令> <关键词>` |
| **开** | 指针 → 原文 | `<命令> open <指针>` |
| **时间** | 按时间窗列事件 | `<命令> timeline --since <ISO>` |

### 3.2 输出契约（★ 这一条决定了门能不能被信任）

**搜的结果必须标明每一条的来源类别。** 建议至少三类：

- `[原文]` —— 一手材料本身
- `[索引]` —— 派生摘要，**必须带回原文的指针**
- `[程序]` —— 机制自己生成的东西（时间戳、状态、统计）

★ 为什么必须标：**不标的话，你会把摘要当成原文引用。**
这是最容易发生、也最难发现的一种记忆污染。

★★ **反面的做法是「只回摘要」** —— 那样搜得又快又漂亮，但你已经不在读历史了，
你在读一个不断被重新生成的故事。

### 3.3 触发清单（★ 这一节的用处比语法大）

门好开，但**得知道要开**。下面任一条命中，**先查再答，不许凭记忆**：

- 用户说「我们之前是不是说过」「你记得吗」「上次」「那次」→ 必查
- 你准备写下「我记得」三个字 → 停，去查
- 涉及具体路径 / 版本号 / 数字 / 文件名 / 哈希 / 端口 → 必查
- 用户指出你记错了 → 先查一遍再回应，不许顺着改、也不许硬撑
- 要回答「谁是主导」「某台机器上有没有 X」「某个配置现在是什么值」→ 必查
- 距上次记录超过 `<N>` 小时 → 先跑一次「时间」
- 心里出现「应该」「大概」「一般来说」→ **那是没查的信号**

★ 一句话判据：**凡是「过去」和「磁盘上」的事实，都不许从记忆里捞。**

★ 反面：**不要为了显得谨慎而滥查。** 当场能看出来的（今天星期几）不用查。
**查得太勤 = 不敢下判断**，那和查得不勤一样糟。

### 3.4 门打不开的时候怎么报

| 症状 | 怎么报 | 绝不能做的 |
|---|---|---|
| 索引过期 | 「索引建于 X，可能是旧的」+ 直接读原文 | 拿旧索引的结果当现状 |
| 文件被移走 | 「按 `<路径>` 找不到，可能是移动了」 | 猜一个新路径 |
| 关键词零命中 | 「`<词>` 零命中」+ 换词再试一次 | 说「没有这件事」 |
| 命中太多 | 「命中 N 条，先按时间过滤」 | 随便挑一条当答案 |

★★ **零命中 ≠ 不存在。** 你可以说「我查过这些词，都没有」，
**但不能说「没有」** —— 前者是事实，后者是推断。

## 四、哨兵（坏了谁发现）

> 一个机制如果坏了没人知道，它就不算机制，算运气。

### 4.1 检查项（填你的）

| 检查 | 怎么查 | 期望 | 失败意味着 |
|---|---|---|---|
| 账本还在长 | `<...>` | 最近 N 小时内有新行 | 写入路径断了 |
| 门能开 | `<...>` | 随机抽一条指针，能打开原文 | 指针语法漂了 |
| 索引可重建 | `<...>` | 删掉后能从权威源重建 | 索引偷偷成了真源 |
| 门牌没有孤儿 | `<...>` | 每条记录的 `ref` 都指得到 | 有人在写无出处的记录 |
| `<你的>` | | | |

### 4.2 分级与退出码

| 级别 | 含义 | 退出码建议 |
|---|---|---|
| `ok` | 通过 | 0 |
| `warn` | 需要人看一眼 | `<非零，例如 1>` |
| `error` | 机制已经不可用 | `<非零，例如 2>` |
| `pending` | 还没跑过 / 待深检 | — |

★ **一定要有 `pending`。** 没有这一级的体检，第一次运行会报一片假绿 ——
而**假绿比红灯更危险**，因为红灯你会去看，绿灯你不会。

### 4.3 盲区（★ 必填）

**这一栏写：哨兵查不到什么。**

```
查得到：账本是否在增长
查不到：账本里记的是不是真的
查得到：指针能不能打开
查不到：打开之后那段话是不是当时真的说过
```

★ 不写盲区，等于暗示「全查到了」。
**一个声称没有盲区的体检，本身就是一条错误的体检结论。**

- [ ] 我把索引删掉，能重建且内容不变
- [ ] 我知道门打不开时该报什么（而不是该猜什么）

★ 五条里第四条最容易被跳过。**跳过它，你会在第一次查不到时开始编。**
