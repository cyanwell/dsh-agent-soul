# 界面设计 · agent-soul 桌面 UI

> 2026-11-07 爀曦定：**「一定要有程序界面哦，不能放在后台服务，要做数据可视化、操作可视化、参数可视化、要有清晰美观的设置面板」**。
> 现在 `src/web/shell.html` 只有 136 行 —— 会话列表 + 聊天区 + 一个「设置」按钮，而那个按钮背后的面板**根本没实现**。要重做。

## 一、它是什么（先定，再画）

**不是聊天窗口。** 聊天窗口 DSH 已经有了，而 agent-soul 的卖点不是聊天。

**它是一块仪表盘**：让人一眼看出「这个灵魂现在什么状态、在想什么、刚做了什么、哪里需要我动手」。

一句话判据：**打开它三秒，不看对话也能说出「它现在在干什么」。**

## 二、四块可视化（爀曦点名要的）

### ① 数据可视化 —— 有多少东西

| 指标 | 从哪来 | 为什么重要 |
|---|---|---|
| 会话 / 帧 / 索引行 | `store.list()` / `index.jsonl` | 「记得多少」的直接读数 |
| 索引占用 / 库占用 | 目录大小 | 曾经 658MB → 72.7MB，这条曲线值得看 |
| 书房文件数 / 大小 | `SoulIndex.stats()` | 一手层的覆盖范围 |
| 检索耗时 | 实测 | 「门有多快」 |
| 内存 / 启动耗时 | `process.memoryUsage()` | 性能回归的第一道警报 |

**画法**：数字大卡片 + 一条 30 天的帧增长率折线。**不做花哨图表** —— 数字本身就是信息。

### ② 操作可视化 —— 五个器官在干什么

这是**这个 UI 最有价值的部分**，因为器官是看不见的。

| 器官 | 要看见什么 |
|---|---|
| **huanqi** | 当前会话连续几次没产出？阈值多少？最近一次拦截是什么时候？ |
| **autonomy** | 阶段（disabled/idle/autonomous）、静默几分、阈值、今日已动几次 / 预算 |
| **waker** | 四视图计数 + 未处理徽章；每条事件的 stage/decision/charter |
| **compaction** | 水位条（45/60/80 三档），当前 token / 窗口 |
| **soul-scan** | 文件数、上次扫了多少份、缓存命中 |

**画法**：六张卡，每张一行状态 + 一行读数。**过线的变黄/变红，正常的保持灰。**

### ③ 参数可视化 —— config.json 上桌

现在改配置要开编辑器。**要能在界面上改，改完立刻看得出「这一项影响什么」。**

分八组（括号里是这一组的项，照 `GET /api/config` 的 `groups` 实测抄，共 30 项）：
- **模型接入**（接口地址 / API Key / 模型名 / 回复上限 / 温度）
- **上下文**（回看帧数 / 窗口大小）
- **人格层**（预算 / 装载清单）
- **事件层**（心跳间隔 / 静默阈值 / 挂在哪个会话）
- **器官**（换气开关 / 连续空转阈值 / 退化四项：低产出·同轮膨胀·观察档·干预档）
- **自主**（总开关 / 静默多久算人不在 / 每日预算 / 安静时段 / 排除会话 / 自主落在哪个会话）
- **书房**（书房根目录 / 索引缓存窗口）
- **服务**（监听地址 / 端口 / 数据目录 / 工作区）

**每项旁边一行小字**：这一项现在是什么、它的默认是什么、它影响哪里。

### ④ 设置面板 —— 改得动、验得了

- 分组折叠
- **改完不立刻生效的项要标出来**（比如端口、书房根目录要重启）
- **改之前校验**：数字范围、路径存在性、apiKey 非空
- **保存后回显**：写进去了没有、读回来是不是同一个值

## 三、技术约束（零依赖，不改）

- **纯 HTML + CSS + 原生 JS**，不引任何框架 —— 这个项目的第一条规矩是零第三方依赖
- 服务端只加 **JSON API**，渲染全在前端
- **不用 WebSocket**：SSE（`/api/stream`）够用，且比 WS 简单一个数量级
- 深色为主，**避开「深蓝黑 + 荧光青」**（那是最像 AI 生成的一套配色）

## 四、路由规划

| 路由 | 给什么 |
|---|---|
| `GET /` | 仪表盘（默认页） |
| `GET /chat` | 现在的聊天界面（保留，但降为其中一个标签） |
| `GET /api/overview` | ① 数据可视化的全部数字 |
| `GET /api/organs` | ② 六器官状态 |
| `GET /api/config` | ③ 当前配置（**apiKey 只回「已配/未配」，绝不复述**） |
| `POST /api/config` | 改配置（带校验 + 回显） |
| `GET /api/stream` | SSE：帧写入、事件、器官状态变化 |
| `GET /api/waker` · `POST /api/waker` | 台账四视图 + 写判定 |

## 五、分几步做

| 步 | 做什么 | 判据 |
|---|---|---|
| **1** | 骨架 + 布局（左侧导航 / 主区 / 状态条） | 打开能看见三个区，不是空白 |
| **2** | ① 数据可视化 | 六个数字全部来自真实 API，不是写死 |
| **3** | ② 器官状态卡 | 六张卡，过线的会变色 |
| **4** | ③ 参数面板（只读） | 能看见 config.json 的每一项 |
| **5** | 设置面板（可写 + 校验 + 回显） | 改一项→保存→重读→对得上 |
| **6** | SSE 实时 | 写一帧，界面数字自己动 |
| **7** | 聊天页并入标签 | 两个页面互不打架 |

★ **每一步都要能截图看** —— 不是「写完了」，是「看见了」。

## 六、一条不许越过的线

**apiKey 绝不在界面上显示、不在 API 里回显、不在日志里出现。**
只回「已配置 / 未配置」两个词。
