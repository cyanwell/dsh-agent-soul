★★ **最后一行是这套设计的核心**：拿不到审核结果时，**既不许「没审就当通过」（放行），也不许「审不了就拦下」（堵死）** —— 标 unchecked、照常叫醒、把原因写进 charterNote。

## 五、已知的两个坑（写下来免得下次再踩）

### ① `session.id` **不带** `session-` 前缀

拼 projcache 路径时是 `'/session-' + sid + '.json'`。
如果谁传了带前缀的目录名，会拼出 `session-session-xxx.json` →
**文件不存在 → 返回 null → 静默降级成「没有 outputTokens」**。
这种错**不报错**，只会让下游一条判据永远不触发。

已加防御：`.replace(/^session-/, '')`。

### ② `readBody()` 返回的**已经是对象**

今天在 `/api/guard` 里写成了 `JSON.parse(await readBody(req))` ——
parse 一个对象会抛错，catch 把 body 变成 `{}`，于是所有请求都说「text 是空的」。
**三条测试全挂，但服务不报错。**

★ 这两条和前面的「`whoHas()` 返回数组不是 id」是同一个形状：
**用别人的 API 之前，先看它到底返回什么。**
