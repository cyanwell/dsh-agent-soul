# 两套代码：部署版与发布版（2026-11-02 · 修订）

## 一句话

**部署端是权威。** 仓库是它的发布镜像 —— 我们先在本机跑通、确认能用，才把改动传到仓库。

所以两边有差异时，**默认的读法是「仓库还没跟上」**，而不是「部署端落后」。

> ★ **2026-11-02 修订说明**：这份文档的初版把方向写反了 ——
> 写成了「发布版是给任何人的、部署版是本机的实验」，等于把部署端当成了二等公民。
> 爀曦原话：**「部署端才是权威，我们是自己跑通之后，才把插件改动传到仓库的。」**
> 初版还漏了 §三 那个真 bug 的形状。

---

## 一、两个住处

| | **A · 部署版（权威）** | **B · 发布版（镜像）** |
|---|---|---|
| 路径 | `<profile>/node_modules/<包名>/` | `dsh-agent-soul/plugins/<目录>/` |
| 本机实例 | `D:\AI\dsh\home\profiles\desktop\node_modules\` | `D:\AI\dsh-tools\dsh-agent-soul\plugins\` |
| 包名 | `dsh-yanqing-*`（还有 `dsh-clock` / `dsh-riji` 等） | `dsh-agent-*` |
| 含本机路径 | 允许 | **不允许** |
| 什么时候动它 | **先动这里** —— 跑通、验证、自己用几天 | 验证完了才动 |
| 给谁 | 只给这台机器 | 任何 clone 这个仓库的人 |

★ 包名不同是**设计的**：本机叫 `dsh-yanqing-echo`，发布出去叫 `dsh-agent-echo`。
但 **`cordis.patch.yml` 里的 `name` 必须等于同目录 `package.json` 的 `name`** —— 这一条不分两边。

---

## 二、什么时候该改哪边

| 场景 | 先改哪边 | 然后 |
|---|---|---|
| 修 bug / 加功能 | **A · 部署版** | 本机验过了，再搬到 B |
| 只跟这台机器有关的（本机路径、本机实验） | **A** | 永远不进 B |
| 验完了、要发布 | **B** | 搬的时候剥掉本机路径、改回 `dsh-agent-*` 包名 |
| 不确定 | 先写进 `30-状态/` 里问 | 别直接改 |

★ **「从 A 搬到 B」是最容易出错的一步**：A 里有本机路径、包名也不同。
直接 `cp` 会把 `dsh-yanqing-*` 带进发布版 —— **必须逐个文件看 diff**。

## 三、那个真 bug 的形状：版本号忘了同步

**症状**：`sync-deployed.mjs` 报某个包两边有差异，一查发现**本机那份是旧的**。

**真因**（爀曦 2026-11-02 指出）：推送更新的时候，在仓库里声明了新版本号，
**但忘了把本机 `node_modules/<包>/package.json` 的 `version` 一起改**。
于是本机跑着旧代码，仓库里写着新版本 —— 两边看着像「仓库领先」。

★ 这不是「该以仓库为准」，而是**漏了一步**：发布的时候要同时改本机的包。

**判据**：两边 `package.json` 的 `version` 不同 → 先怀疑自己漏改了本机那一份，
而不是去怀疑代码。

## 四、现在差多少（2026-11-02 实测）

`node tools/sync-deployed.mjs` 输出：**15 / 15 个包有差异**。

- **A 有、B 没有的**（还没传上去的改动）：pruner 的自动触发（+130 行，未验证，暂不发布）、
  huanqi-panel（+92 行）、memory（+8 行）
- **B 有、A 没有的**（大概率是 §三 那个形状）：clock 的 client、compaction、riji、model-statusbar
- **只在 A**：`dsh-yanqing-chat` / `-line` / `-pet` / `-triad` / `-voice` / `comfyui-panel` /
  `mimo-agent-tools` / `clawbot` / `dsh-yanqing-3d` / `dsh-yanqing` —— **这些不发布**，
  它们不是 agent-soul 的组件（爀曦 2026-11-02 定）
- **只在 B**：`dsh-agent-mnemon-probe`

## 五、怎么查

```bash
node tools/sync-deployed.mjs                          # 列差异（只读）
node tools/sync-deployed.mjs --fail-on-diff           # 有差异就 exit 1
node tools/sync-deployed.mjs --deployed "<另一个 node_modules>"
```

## 六、三个已经踩过的坑

1. **不要用 mtime 判「谁新」。** 仓库文件的 mtime 会被 `git checkout` 刷新。
   第一版对账工具就是这么干的，报了 15 个假「部署落后」。
   比版本号，或者直接看 diff。
2. **包名不能直接比。** A 是 `dsh-yanqing-<x>`，B 是 `dsh-agent-<x>`。
   判据：剥掉前缀后尾段相同 —— `sync-deployed.mjs` 里的 `keyOf()`。
3. **`lib/` 要比。** 本机的 `dsh-yanqing-huanqi` 跑的是 `lib/index.js`（编译产物），
   而 `src/index.ts` 只在发布版有。排除 `lib` 会让你看不见真正的宿主机代码差异。

## 七、和 organs 那次的关系

`tools/sync-plugins.mjs` 是给旧的 `plugins → dsh-agent-organs` 用的，
那个仓库 2026-10-30 已弃用并删除 —— **它现在跑起来只会 exit 2**。
两个住处的关系从「三个」变成了「两个」，工具和文档一起换了。
