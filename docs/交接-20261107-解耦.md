## 二、做完的（有实测读数）

### `tools/soul-sync.mjs` —— DSH → v4 增量同步器

**只读 DSH 的日志文件，不进 DSH 进程。** 这是他自己选的 C 方案：

```
D:\AI\dsh\home\sessions\<工作区>\<会话id>\session.v4.jsonl.zstd
        ↓ soul-sync（只读）
D:\AI\agent-soul\data\sessions\<会话id>\frames.jsonl  +  index.jsonl
```

**实测**：

```
首次  扫 1014 个会话 → 2874 帧进 10 个容器
立刻重跑 → 0 帧                       ← 增量生效
搜「灵魂服务」→ 命中 04:20 那句原话     ← 十分钟前的话，它记住了
```

**自检**：`tools/sync-selftest.mjs` —— **11 项 / 0 失败**。
（覆盖：能解析 / 增量 / 不重复 / 水位丢了也不重写 / 索引非空 / header 帧计数）

★★ **修掉一个会毁数据的 bug**：水位文件不存在时 `seen=0`，会把已迁的 1008 个会话全当新的，
dry run 显示要写 **16 万重复帧**。改成从容器自身帧里推 `meta.seq` 最大值当初次水位。
（`append` 不查重，写进去就是双份 —— 这个如果不发现，数据会废。）
