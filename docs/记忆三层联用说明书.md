# 记忆三层怎么联用 · 操作说明书

> 2026-10-25 写。这篇不讲架构（那是 `docs/ECHO-权威口径.md` 的事），
> 讲的是**实际每天怎么用这三套东西，以及它们为什么必须一起用**。
>
> 如果你只想知道「什么时候往哪写、什么时候去哪查」，跳到第二节和第四节。

---

## 一、三者的真实分工

先分清它们**各自不做什么** —— 这比记住它们做什么更有用。

| | 是什么 | 存什么 | **不**存什么 |
|---|---|---|---|
| **ECHO（回声面板）** | **观测层**。`echo-doctor.mjs` 每轮扫日志，把状态摆出来 | **状态**：门牌有没有失效、索引新不新、压缩还活着吗、热记忆满没满、版本有没有漂 | **不存任何内容**。它只有仪表，没有货舱 |
| **墨 + 书房** | **一手层**。`02-墨.jsonl` 是只追加的账本，书房是文件 | **事件**：承诺（promise）、决定（lead）、得、失、搁置、人格、日记 | **不存可复用的技术结论**。事件检索准，但「这类问题我们下过什么结论」它搜不好 |
| **mnemon** | **结论层**。Memory Space，带语义检索和图关系 | **判据**：踩过的坑、可复用的判据、本机怪癖、检测法 | **不存事件经过**。没有时间线，问「那天发生了什么」它答不准 |

**再加一个容易被忽略的位置：热记忆（`MEMORY.md`）。**

它是**每轮注入**的，所以它装的必须是「不看会踩坑」的那类 —— 不是档案，是**缓存**。
判断一条该不该留在热记忆里的唯一标准：**删了它，我下次会不会犯同一个错？**
会 → 留；只是「有点意思」→ 挪走。

---

## 二、协同在哪（不是三套记忆叠加）

很多人以为「记忆越多越好」。不是。**这三层是闭环，各自补别人的盲区：**

```
      写                        读                      验
   ┌────────┐            ┌──────────────┐        ┌──────────┐
   │ 事件→墨 │            │ 先 memq(准)  │        │  ECHO    │
   │ 判据→   │            │ 再 recall(广)│        │  体检台  │
   │ mnemon  │            └──────────────┘        └──────────┘
   └────────┘
```

- **没有 ECHO，前两层是盲的。** 我不知道门牌还在不在、索引是不是过期了、
  热记忆是不是已经满了却还在往里塞。**记忆系统坏了不会报错，它只会安静地失忆。**
- **没有前两层，ECHO 只是一张空表。** 它能报「压缩事件 51 条」，
  但「那 51 条压的是什么、指得回哪里」只有一手层答得出来。

所以三者的关系是：**一手层是货，mnemon 是索引卡，ECHO 是仓库的监控屏。**
缺一个，另外两个的价值都会打折。

### 一个真实的例子（2026-10-25，最有说服力）

那天要验证「路 B 在 rc.3 上到底成没成立」。我的做法是：重启七次、写探针包、
往已经跑着的压缩包里塞日志 —— 全部失败，拿不到 ctor。

**而 ECHO 早就报了：`doorsign ok seq=125313`。** 门牌一直是通的。

后来一次真实压缩发生，摘要首块写了：

```
log:session-1099f531-7cac-4989-a14c-7fd499ac1fc0#seq=126331（本段覆盖 126331–126653）
```

还带了回取命令。**答案一直在，我是去造了一个更难的答案。**

★ 这一条写进说明书，因为它是这套系统最容易被用错的地方：

> **ECHO 的历史记录本身就是证据。**
> 它每轮都在采样；需要证据时，**先去读历史，再决定要不要造新的。**
> 「体检台报绿灯」不等于「不用验」，但它意味着**你该先看一眼，而不是先动手。**

## 三、写：什么时候往哪写

一张判据表，按「这件事的形状」选，不按「我觉得重要不重要」选。

| 你手上是这种东西 | 写到哪 | 为什么 |
|---|---|---|
| 一次决定、一句承诺、一次得失、一段情绪 | **墨**（`mo.mjs add`） | 有时间、有署名，将来能「翻回去」 |
| 一个会再踩的坑（含检测法） | **mnemon**（`mnemon_remember`） | 判据要能被语义搜到，不该埋在某天的事件里 |
| 本机怪癖（工具行为、路径规则、环境限制） | **mnemon** | 同上。跨会话可复用 |
| 一条必须每轮都看见的硬约束 | **热记忆** `MEMORY.md` | 它每轮注入，贵，所以只放最要紧的 |
| 一份要给人看的长文档 | **书房文件**＋`40-产物索引` | 墨只记「我写了它」，正文在文件里 |
| 一个「待做但先搁置」的活 | **墨** 的 `shelved`，或砚台甘特图 | 前者记状态，后者记排期 |

★ 一条纪律：**同一件事不要重复写三份。** 事件进墨，从事件里提炼的判据进 mnemon，
墨里那条只需要写「从这件事得出一条判据，已入 mnemon」——**不复制正文**。
复制是记忆系统最常见的腐烂方式：两份内容，改一份忘另一份。

## 四、读：什么时候查哪边

| 要回答的问题 | 查哪 | 命令 |
|---|---|---|
| 「那天到底发生了什么」 | 一手 | `memq.mjs <词>` / `memq.mjs open <指针>` |
| 「我们以前对这类问题下过什么结论」 | mnemon | `mnemon_recall` |
| 「现在几点、距上轮多久、谁在主导、还有什么没结」 | 一手（时钟） | `memq.mjs now` |
| 「这套东西现在还活着吗、哪里坏了」 | ECHO | 面板，或命令行跑 `echo-doctor.mjs` |
| 「某个配置现在是什么值」 | **都不是** —— 去读文件 | 记忆里的事实会过期，磁盘上的不会 |

★★ 最后一条是硬规矩：**凡是「过去」和「磁盘上」的事实，都不许从记忆里捞。**
版本号、端口、哈希、某个字段现在是什么 —— 这些都会变，而记忆是快照。
查记忆得到的是「上次它是什么」，不是「它现在是什么」。

★ 拿不准先查哪个：**先 `memq`（一手更准），再 `recall`（跨会话更广）。**
因为一手带门牌、能一路回到原文；mnemon 是提炼过的，适合「我不知道该搜什么词」的时候。

## 五、四个常见误用（都真实发生过）

| 误用 | 后果 | 正确做法 |
|---|---|---|
| 把事件写进 mnemon | 浪费。mnemon 没有时间线，问「那天的经过」它答不准，而 memq 一搜就到 | 事件进墨；mnemon 只收提炼后的判据 |
| 技术结论只写一手 | 漏。半年后在别的会话里想不起关键词，一条都搜不到 | 判据必须进 mnemon |
| 把 ECHO 当记忆用 | 它只有状态没有内容，问它「上次压的是什么」它答不出 | ECHO 用来**发现问题**，解决问题去一手层 |
| 为了「保险」把东西抄进热记忆 | 热记忆每轮注入，抄多了挤掉真正要紧的，而且满了会**静默丢最宽泛的** | 只放「不看会踩坑」的；其余挪走 |

## 六、日常一次完整循环长什么样

以「修一个 bug」为例，把三层都走一遍：

1. **踩坑** → 墨记一条 `fact` 或 `loss`：什么现象、当时怎么判断的
2. **查明真因** → 提炼成判据，`mnemon_remember`：**判据 + 检测法**，别只写「踩过」
3. **改代码** → 按发布纪律：代码 / 更新公告 / 文档口径同一个 commit
4. **隔几轮回头看** → ECHO 面板确认：压缩还活着吗、门牌还有效吗、索引新不新
5. **下次遇到同类问题** → `mnemon_recall` 直接命中第 2 步的判据，不用重新踩

★ 第 5 步是这一整套东西唯一的目的：**让你不用在同一个坑里摔第二次。**
如果一条判据写进去之后再也没被读到过，那它只是自我安慰 ——
所以第四节那张「什么时候查哪边」，比第三节的「往哪写」更重要。

## 七、边界（这套东西做不到什么）

说实话，这部分和前面同样重要：

- **mnemon 不是数据库。** 它的检索是语义的，不是精确的。要精确匹配某个字符串，去 grep 日志
- **ECHO 不修东西。** 它只报警。报警之后要人去查，它自己没有任何自愈能力
- **墨只追加，不能改。** 写错了不能回头篡改 —— 那是设计，不是缺陷。改主意就再追加一条说明
- **热记忆会满。** 满了之后最宽泛的内容会被静默丢掉，而**你不会收到通知**。
  所以它必须定期量（面板上那一行 `MEMORY 9条/6.9KB(69%)` 就是干这个的）
- **这三层都救不了「根本没记」的东西。** 它们只保证「记过的能找回来」，
  不保证「该记的都记了」—— 后者是判断力，不是系统能力

---

## 八、一句话总结

**墨记住发生了什么，mnemon 记住学到了什么，ECHO 记住这套东西还活着没有。**

三个都在的时候，你才敢相信「我记得」这三个字；
少一个，你就得靠翻日志，而翻日志的前提是你还记得该翻哪里。
