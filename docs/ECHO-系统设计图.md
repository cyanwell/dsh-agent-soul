> **2026-10-31 · 冻结版**

## 〇、冻结声明（先立规矩）

**从 2026-10-31 起，六层的编号、名字、职责不再变。**

| 冻结点 | 内容 |
|---|---|
| **六层编号** | L0–L5，一个不多一个不少 |
| **层职责** | 每层管什么，见 §1 |
| **L2 是唯一可丢的层** | 这条不许动 |
| **门牌格式** | `log:<会话>#seq=<n>` / `idx:<id>` / `file:<路径>:<行>` |
| **原文路线** | 只追加不删、100% 可回源 |
| **哨兵不是层** | 它是观测面 |

**可以改的**：
- 每层内部的实现（比如 L5 的检索算法）
- 每层的容量/预算（比如 L4 常驻天数）
- 新增「内容」（比如新的记忆类型）
- 性能优化

## 一、六层总览（唯一口径）

```
┌──────────────────────────────────────────────────────────────┐
│                        ECHO · 生命核心                        │
│                      「我是谁 / 我记得什么」                   │
│                                                              │
│  失败形状只有一种：丢掉的东西找不回来（门牌失效）               │
└──────────────────────────────────────────────────────────────┘

  L0 时钟 + 心跳 ────────────────────────────────────────
  │  现在几点 / 距上轮多久 / 当前 lead / 未结
  │  每天 04:00 自动跑索引重建 + 四项自检
  │  📁 hub\state.json · hub\heartbeat\ · memq now
  │
  L1 自我 + 热记忆 ──────────────────────────────────────
  │  ① SELF.md     定长骨架，每轮注入（不变量/硬线/约束三级/门）
  │  ② USER.md     用户画像，每轮注入
  │  ③ MEMORY.md   工作参考，每轮注入
  │  📁 hub\SELF.md · C:\Users\pc\.mnemon\runtime\
  │  ⚠ 有独立预算：SELF 12288B · USER 4096B · MEMORY 10240B
  │
  L2 工作台 ─────────────────────────────────────────────
  │  当前对话上下文
  │  ★★★ 六层里【唯一】允许丢东西的一层
  │  📁 会话本身（不在磁盘）
  │  ← 换气/压缩/裁剪 只动这一层
  │
  L3 一手层 ─────────────────────────────────────────────
  │  ① 会话日志  2061 个文件 / 761 MB（zstd 压缩态）
  │  ② 《墨》     02-墨.jsonl（只追加）
  │  ③ 书房       D:\AI\yanqing-soul\（3568 文件/164 目录）
  │  ④ 留底库     D:\AI\memory\
  │  📁 各写各的（只追加，永不删改）
  │  ★★ 这一层丢了 = 事故，不是设计
  │
  L4 索引 + 图记忆 ──────────────────────────────────────
  │  ① 索引：摘要 1151 / 原话 51749（每条带 srcSeqs 指针）
  │  ② 图记忆：mnemon 洞察 + 关系边（语义检索用）
  │  📁 hub\index\ (summaries/words/files.jsonl)
  │  📁 mnemon (holographic provider)
  │  ★★ 没有指针的摘要不许进这一层
  │
  L5 检索 + 门牌 ────────────────────────────────────────
  │  memq 一扇门四动词：now / <词> / timeline / open
  │  门牌：log:<会话>#seq=<n> · idx:<id> · file:<路径>:<行>
  │  📁 hub\memq.mjs · hub\echo-mcp.mjs（MCP 入口）
  │
  └─────────────────────────────────────────────────────

  ┌─ 观测面（不是层）──────────────────────────────────┐
  │  哨兵 echo-doctor.mjs · 十项体检（普通 + 深度两档）  │
  │  ★ 它测「哪层坏了」，不产出记忆、不决定保留什么      │
  └──────────────────────────────────────────────────┘
```

## 二、写入路径（数据怎么进来）

```
        ┌────────────┐
  对话 → │  L2 工作台  │ ← 换气/压缩/裁剪 在这里工作
        └─────┬──────┘
              │ turn/end
              ▼
        ┌─────────────────────┐
        │  宿主写会话日志        │  session.v<N>.jsonl.zstd
        │  （多帧 zstd）        │  位置：D:\AI\dsh\home\sessions\<ws>\<sid>\
        └─────┬───────────────┘
              │ 每天 04:00 心跳
              ▼
        ┌─────────────────────┐
        │  memindex build     │  逐帧解码 → 按行切 → 提摘要 + 原话
        │  （42 秒 / 全量）    │  ★ 2026-10-23 修：不再 concat 成巨串
        └─────┬───────────────┘
              ▼
        ┌─────────────────────┐
        │  L4 索引             │  summaries.jsonl（14.6MB）
        │                      │  words.jsonl（50.6MB）
        │                      │  files.jsonl（0.9MB）
        └─────────────────────┘

  另一条并行的写路径：
  我写 → 02-墨.jsonl（只追加）→ 直接进 L3，不需要索引
  我写 → 书房文件 → 直接进 L3，被 echo-mcp 的 C.soul 缓存
```

**★ 关键：L3 是「宿主/我」写的，L4 是「心跳」写的。两者解耦。**

## 三、读取路径（数据怎么出来）

### 3.1 两条入口

```
┌─ MCP（默认，18-57ms）──────────────────────────────┐
│  agent ──→ mcp__echo__echo_search                  │
│            └→ echo-mcp.mjs（mcp-hub 常驻）         │
│                 └→ 内存里的 C.words/C.sums/C.mo     │
└────────────────────────────────────────────────────┘

┌─ CLI（MCP 不通时才用，773ms）──────────────────────┐
│  终端 ──→ node memq.mjs <词>                       │
│           └→ 起 node 进程（450-500ms 硬底噪）       │
│                └→ 连 echo-svc（pipe）               │
│                     └→ 同一个内存态                 │
└────────────────────────────────────────────────────┘
```

### 3.2 检索的六步（一次 search 的完整流程）

```
① refresh()          检查索引文件 mtime，变了才重读
       │
② 扫 C.mo            616 条墨
       │
③ 扫 C.sums          1151 条摘要
       │
④ 判 idxTotal < 5？
       ├── 是 → ⑤ 扫书房（C.soul，带 5 秒 TTL）     ← 737ms 的代价在这里
       └── 否 → 跳过书房
       │
⑤ 扫 C.words         51749 条原话                  ← 66ms（命中）或 547ms（未命中）
       │
⑥ hits.sort()        L3 优先 → 按时间倒序
       │
       └→ 返回 hits[]（带 ptr 门牌）

★ near=true 且未命中时：第⑤步会额外对每条做 norm() → +547ms
```

### 3.3 门牌的三种形态

| 门牌 | 指向 | 打开命令 |
|---|---|---|
| `log:session-xxx#seq=123` | 会话日志的某一行 | `memq open` |
| `idx:cmp-8f3a2b` | 索引摘要 | `memq open` |
| `file:D:\path\x.md:42` | 书房文件的某一行 | `memq open` |

## 四、实测基线（2026-10-31，这台机器）

### 4.1 各层体积

| 层 | 项 | 体积/数量 |
|---|---|---|
| **L1** | SELF.md | 10721 B / 12288（87.2%） |
| | USER.md | 3300 B / 4096（80.6%） |
| | MEMORY.md | 9898 B / 10240（96.7%） |
| **L3** | 会话日志 | **2061 文件 / 761 MB**（压缩态） |
| | 《墨》 | 616 条 |
| | 书房 | **3568 文件 / 164 目录** |
| **L4** | 摘要 | **1151 条 / 14.6 MB** |
| | 原话 | **51749 条 / 50.6 MB** |
| | files | 0.9 MB |
| **L5** | echo-mcp RSS | **250 MB** |

### 4.2 各操作耗时

| 操作 | 耗时 | 备注 |
|---|---:|---|
| MCP 查询（中文命中） | **18-57 ms** | 中位数 |
| MCP 查询（英文/冷门词） | **260-380 ms** | 触发书房全扫 |
| CLI + svc | **773 ms** | 起 node 的底噪 |
| CLI 无 svc | **3121 ms** | 每次重建 |
| **`norm()` 51749 条** | **547.8 ms** | near 未命中的全部开销 |
| `includes` 51749 条 | **66.4 ms** | 命中路径 |
| 书房全扫（walk+stat） | **737 ms** | soul=auto 命中<5 时 |
| 索引全量重建 | **42 秒** | 心跳每天 04:00 |
| MCP 启动预热 | ~1.2 s | 读索引 |

### 4.3 内存预算（1GB 可用，当前 250MB）

| 项 | 内存 |
|---|---:|
| 索引原话解码 | 183 MB |
| 预计算 norm | +111 MB |
| 2-gram 倒排 | +226 MB |
| 会话日志 3 天 | +212 MB |
| 向量（摘要层） | +1.7 MB |

## 六、不能碰的边界（红线）

| # | 红线 | 为什么 |
|---|---|---|
| 1 | **L2 之外不许丢东西** | 这是六层的地基 |
| 2 | **没有指针的摘要不许进 L4** | 门牌失效 = ECHO 的唯一失败形状 |
| 3 | **检索只回指针 + 逐字片段，不做转述** | 转述是二手污染 |
| 4 | **拿不到精确 seq 就给检索入口，绝不猜** | 错的门牌比没有更坏 |
| 5 | **原文只追加，永不删改** | 847/847 可回源的来源 |
| 6 | **哨兵只跟口径，不改布局** | 它是观测面，不是层 |
| 7 | **别让两个地方同时是真相** | 权威口径存在的全部意义 |
