# agent-soul 是什么，不是什么

> 2026-11-07 爀曦定音：「其实只是把 agent soul 架构独立出去，不是单独做成一个 harness」

我在这句话之前做偏过一次 —— 顺手做了 LLM client、工具注册、回合循环。
**那些是 harness 的活。** 写在最前面，免得下一个人（包括我自己）又往那个方向漂。

---

## 两句话（2026-11-07 补 · 缺一句就会读歪）

> **定位上**：它是记忆层，不是聊天运行时。
> **能力上**：它已经能自己起回合、跑工具、管会话 —— 够格当一只小 harness 用。

★★ **这两句必须一起读。** 爀曦同一天说过两句看似相反的话：

| 时间 | 原话 | 说的是什么 |
|---|---|---|
| 03:28 | 「其实只是把 agent soul 架构独立出去，**不是单独做成一个 harness**」 | **划边界** —— 别把主语搞错 |
| 03:47 | 「卧槽，agent soul 架构被你**硬生生做成 harness** 了」 | **看实物后的判断** —— 它真能跑 |

★ 只读第一句 → 会把已经造好的能力拆掉（我第一次就做偏了，去掉了 LLM client 又加回来）。
★ 只读第二句 → 会把它当成「又一个聊天软件」，然后开始往里塞 harness 该干的活。

**判据**：问「这件事该由谁做」时，用第一句；问「它现在能干什么」时，用第二句。

## 一句话

**它是一套能被任何 harness 接上的「记忆与身份层」。**

不是「又一个聊天运行时」。它不负责想，负责**记得住、翻得回、说得清自己是谁**。

---

## 它解决的四件事（别人也有，但没人把它做成独立可插的）

| | 是什么 | 为什么别人没有 |
|---|---|---|
| **会话仓** | 每一帧原文落盘 + 实时索引 | 各家 harness 的会话日志是**给调试看的**，不是给你「翻回去」用的 |
| **索引** | 写时就建，不是事后扫 | 压缩带索引会漂；这里 `append()` 一次写两份 |
| **人格分层** | core / work / context，各有预算，超了**说清丢了什么** | 别人的 system prompt 是拼出来的，不是「层」 |
| **账本** | 只追加，`promise` 有代码闸门 | 别人靠「请记得不要」，这里靠「你写不进去」 |

---

## 边界：它不知道的三件事

这三条**必须说清**，因为它们是最容易被「看起来像」骗过去的地方：

| 它做不到 | 为什么 | 它怎么说 |
|---|---|---|
| **不知道你宿主的上下文水位** | 那是宿主的私事 | `soul_context` 会明说「这是本软件自己这个容器的，不是你宿主的」 |
| **不知道 Mnemon 实际注入了几条** | 热记忆不走 system prompt，是每轮当消息注入的 | `soul_mnemon` 的 `injected` 恒为 `null`，不编数 |
| **不替你决定谁是主导** | `lead` 的权限在爀曦嘴里，不在代码里 | 器官写 `promise` 会被 `NOT_BRAIN` 拒 —— **不依赖它记得，依赖它写不进去** |

## 两层架构（这才是「解耦」的形状）

```
┌─ 任何 harness ─────────────┐
│  DSH / Codex / Claude Code │  它有它自己的回合、工具、模型
└────────────┬───────────────┘
             │  MCP（stdio 或 HTTP）
             ▼
┌─ agent-soul ───────────────┐
│  15 个工具：                 │
│    读写帧 / 检索 / 取原文     │
│    取人格 / 建索引 / 会话列表 │
│    账本（有闸门）             │
│    事件层（心跳 + 唤醒）      │
│    器官（换气 / 自主 / 压缩） │
│  七页界面（数据/操作/参数可视）│
└────────────────────────────┘
```

★ **它自己也能起一个回合**（`src/agent/loop.mjs`）—— 但那是**为了自测**，
  不是它的主业。真正用它的时候，回合在宿主那边跑，它只被调。

## 接法（三种，从最松到最紧）

### ① 只当 MCP 服务器（最常用）

在宿主 config 里写一段 stdio：

```json
{"serverName":"agent-soul","transport":"stdio",
  "command":"<node.exe>","args":["<agent-soul>/src/adapters/mcp.mjs"]}
```

宿主就多出 15 个工具。它不抢回合、不抢模型、不抢工具列表。

### ② 用它的 HTTP 端点

`http://127.0.0.1:<port>/mcp` —— 同上，只是走 HTTP。
同一个端口还挂着七页界面。

### ③ 当成库用

```js
import { SessionStore } from './src/session/store.mjs';
import { Query } from './src/tools/query.mjs';
import { PersonaLayer } from './src/persona/layer.mjs';
```

---

## 什么时候不该用它

- 你只是想要一个能跑的 agent → **用宿主自带的就好**，多一层没好处
- 你要的是「模型更好」 → 这跟它没关系
- 你要的是「多工具」 → 宿主自己的工具生态更全

## 一条今晚学到的教训（写在这里，因为它会再发生）

**同一个项目里有两个 exe，名字不同，都不报错。**

我在 `launcher.exe` 里改了启动器，编译通过、文件也对 —— 
但 `package.mjs` 打包用的是 `agent-soul-dev.exe`，那是 02:38 的旧版。
**改了 A，跑的是 B。**

这和「写入成功、检索也返回结果，只是返回的不是你要的那条」是同一种形状。
**两个都不报错。** 所以排查的时候，第一步永远是：

> **我验的，真的是我改的那个东西吗？**
