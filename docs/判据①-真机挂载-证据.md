## ★ 修这条判据时抓到的一个真 bug

**`searchAll` 是「先到先得」，不是「按相关度」。**

```js
// 修之前
for (const sid of this.ix.keys()) {
  for (const row of this.search(sid, needle)) {
    out.push(...);
    if (out.length >= limit) return out;   // ← 满了就回，后面不看了
  }
}
```

遍历顺序 = Map 插入顺序 = 会话目录名顺序。
**排在前面的会话只要有一个字碰上，就占满名额** ——
后面那些真正相关的、或者**刚写进去的**帧永远轮不到显示。

### 怎么发现的

`data/sessions` 里有 **1009 个真实会话**（迁移来的）。
在空数据目录上跑，命中；在 1009 个会话上跑，**命中 0** —— 而那一帧明明在索引里、`soul_frame` 按 seq 能读到。

★ **这个形状最坏**：写入成功、检索也返回结果，**只是返回的不是你要的那条**。
  不报错、不空转，安安静静给你一个错的答案。

### 修法

全部收齐 → 按 score 排序 → 再截断。
代价是遍历全部会话（实测 113ms / 1009 个会话）；换掉的是「悄悄给错的答案」。
