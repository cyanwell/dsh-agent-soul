# archive · 沿革

> 读的人会拿它当现状** —— 而那比没有文档更坏。

## paper/

`echo-architecture.html`（约 76 KB）+ `README.md`

那是**某一版**的架构论文，写得比较完整 —— 五层模型、判据、门牌纪律都在里面。

**但它跟不上了。** 架构在写完它之后又改过几轮，有些判断被推翻了，
有些机制换了形态。所以：

| 你要找的 | 该看哪 |
|---|---|
| **现在**该有什么 | `../soul/` 那十份 |
| **现在**长什么样 | `../skeleton/` 那五份 |
| **现在**装什么 | `../plugins/清单.md` |
| **曾经**怎么想的 | ★ 这里 |

★ 论文里仍然有价值的部分：**它把「为什么这么设计」讲得比 soul/ 更完整。**
soul/ 是判据（短、能拿去问候选人），论文是叙事（长、能读懂动机）。
两者不冲突 —— 只是**结论以 soul/ 为准，动机可以回来看论文**。

---

## 怎么用沿革

按 `soul/01-criteria.md` 的那条纪律：

> **读物回答「现在是什么样」，沿革回答「改过什么、被什么推翻过、证据在哪」。**
> **沿革是证据，不是结论。**

所以：**不要拿这里的任何一句话当现状引用。** 要引用现状，去 soul/。
要用这里的某一句话，先确认 soul/ 里还是这么说。
