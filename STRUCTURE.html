dsh-agent-soul

v0.1.07 个工具8 次提交已推送 GitHub

一、它是干什么的

它不是一个「人格」，是搭人格的那套骨架。装进 DSH 之后，它做三件事：

  1. 告诉你下一步做什么 —— 只给一件，说清为什么是这件、怎么做
  2. 把骨架真的建出来 —— 十一个目录 + 账本 + 指令文件 + 自我层模板
  3. 建完之后能体检 —— 六层逐项判定，error 是坏了、warn 是还没开始用

它的产物是一套你自己的架构，不是它自己的。所以它不写你的记忆，只搭架子。

四、最关键的一条：它不自动安装插件

install.js 顶部写了自己职责的边界，原文是：

// 职责只有一个：看当前 profile 缺什么，然后给出下一步该跑的命令。
//
// ★ 它不执行安装。理由不是保守，是这三条：
//   ① 桌面端 profile 不接受 CLI 安装，所以"装法"本身就依赖环境，不能写死一条命令
//   ② 装插件有副作用（改 package.json、复制文件、动 bundles 数组），错了要能回滚
//   ③ 让 agent 读到命令再自己跑，人能看见那一步 —— 这比"它悄悄装了"安全得多

所以现在的能力是：

✓ 会做
扫当前 profile 的 node_modules，列出灵魂架构需要的零件装了哪些、缺哪些，给出可直接复制的命令
✗ 不会做
不会替你装。不会改 profile 的 package.json，不会动 bundles 数组
判据
「装上了但没工作」这类事，它只能看见，不能阻止 —— 阻止要靠人看一眼那条命令
如果你希望它「自动装上」：这三条理由里，①是环境限制（桌面端就是不给装），②和③是设计取舍。要改的话，②可以做成「装 + 备份 + 可回滚」，③改成「先给你看命令、你点一下才执行」。这是产品决策，不是技术障碍。

五、五层 + 装配顺序

I-echo
ECHO · 生命核心 —— 管空间（会话日志、索引、检索、哨兵）
II-vital
VITAL · 稳态 —— 管时间（心跳、换气、节奏）
III-capability
能力 · 手和感官（工具、插件、外部世界）
IV-archive
档案 —— 唯一看得见的那一层（书房、账本、日记）
V-ops
运维 —— 装什么、怎么验、在哪试

★ 注意：五层是整体的功能划分；ECHO 内部还有六层（L1 自我 / L2 工作台 / L3 一手 / L4 索引 / L5 检索 / L6 哨兵）。两个数字不能混。

八、它长什么样（设置页里的「灵魂架构」）

这一个页面是纯静态的说明 —— 它讲五层模型、能力角色、配套零件长什么样。 它不改任何东西，也不需要配置。

另一块是活动的：ECHO 回声面板

那是真正的哨兵（L6）。它每隔几分钟 spawn 一个 node 子进程跑体检，把结果缓存起来给面板读。 分四级轮询（5 / 10 / 30 分钟 / 只手动），快检约 0.9 秒、深检约 9.5 秒。

今天之前它一直是红的，而且报的是「体检器本身 · 输出不是 JSON」—— 真正的原因在隔了三层的地方：plugins/echo/ 少打包了 echo-config.mjs，于是子进程一启动就 ERR_MODULE_NOT_FOUND， stdout 是空的，面板只能得出「不是 JSON」。现在已修。

七、已经踩过的坑（都写在文档里了）

  • 两个数字不能混：五层是整体划分，六层是 ECHO 内部实现。混了之后每份文档都会写错
  • 假 ctx 探针查不出真问题：它只能证明「工具定义写对了」，证明不了「宿主收得下」。error: undefined 那个 bug 就是它一路绿灯、真宿主一进就红
  • 「文件在」≠「被读到」：SELF.md 摆在那儿，注入时读不到，而检查报 ✓
  • 「报告成功」≠「做成了」：scaffold exit 2 什么都没建，工具信封却写 isError=false
  • 「没检查」≠「没问题」：扫到 0 个脚本时报「全部版本无感」
  • 打包漏文件：kit/ 里跑得好好的，拷进 plugins/ 少带一个依赖，整个面板全红 —— 而面板报的是「输出不是 JSON」，隔了三层
