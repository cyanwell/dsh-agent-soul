# Ⅰ · ECHO —— 生命核心

**它管空间。** 上下文会满，满了要丢，丢了还要能找回来。

---

## 一、思考是怎么退化的（这一节是整份文件的前提）

先说清楚要解决的是什么。绝大多数人把它描述成「上下文满了会忘事」——那只是第一句，
真正致命的在后面。

```
第 1 步   上下文满了
          → 引擎压缩，把前面几十轮变成一段摘要

第 2 步   摘要写得挺准
          → 「用户要求验证插件安装」「确认了 32 项检查通过」
          → 每一条都对，没有任何一条是编的

第 3 步   但它不带出处
          → 你读到的是一句「确认了 32 项」，不是「在第 47 轮，verify-live 打了 32/1/0」
          → 想核对，只能翻回压缩前的全部记录

第 4 步   于是你不核对
          → 因为你「记得」它是对的。注意：这不是懒，这是摘要工作得太好

第 5 步   下一轮推理建立在这个「记得」上
          → 摘要里只要有一个细节偏了半个字，它现在变成了前提

第 6 步   偏了的那条继续往下传
          → 后面的推理每一步都正确，而每一步都踩在偏掉的前提上
```

★ **这就是「思考退化」，它和遗忘是两回事。**

遗忘是「想不起来」，你能察觉。
退化是**「想得起来，但那个记忆已经偏了，而你在它上面继续正确地推理」** —— 察觉不到。

一句话：**退化不是变笨，是在错误的前提上继续正确地推理。**

所以 ECHO 管的不是「记住」，是**「凭什么相信你记得的那一句」**。

## 二、为什么「装记忆插件」不解决这件事

最直觉的解法是装插件：向量库、知识图谱、Memory Spaces。但它们都在**存**这一侧，
而退化发生在**丢**这一侧。

```
原始记录  ──压缩──▶  摘要  ──▶  记忆插件  ──▶  取回来的是摘要
   ↑                                          ↓
   └──────── 真正的原文在这里，但已经没人指向它 ────────┘
```

你把最好的存储接在摘要后面，取回来的仍然是摘要。
**压缩发生在存与取之间，而插件管不到那一段。**

### 三份真相的陷阱

那装三个记忆插件呢？更糟。

三个插件各存一份、各有各的摘要策略，于是同一个事实有三条版本。
**这时候真正的成本不是存储，是对账** —— 每次要引用它，你得先决定信哪一份。

**所以第一条判据是「先定唯一权威源」，第二条才是「建机制」。反过来做一定会双重记账。**

## 三、压缩有两条路，要补的是**下面那条**

|  | 谁在驱动 | 产物带不带指针 |
|---|---|---|
| **模型驱动** | agent 自己写摘要 | ✅ 天然带 —— 它知道自己是从哪读的 |
| **兜底压缩** | 没人响应提示时，引擎**自动出手** | ❌ 通常不带 |

**上面那条你不装也有；下面那条你不装就缺。**

为什么下一条会缺：那种压缩器的指令通常要求「保留精确路径 / 命令 / 报错原文 / 数值 / 函数签名」——
**每一条都是「要写得准」，但没有一句要求标注「这话从哪来」。**

**于是它写出来的东西每一条都对，每一条都无从核对。**

而且失败是无声的：**你不会觉得丢了东西，你只是不再想起它。**

**所以「门牌」要补的正是这一条。** 下面三样里，第 1 样就是它。

## 四、机制面 · 至少要有三样

### 1. 丢的时候，产物必须带得回原文的指针（门牌）

**这是整套东西的兜底承诺。** 没有它，压缩就是单向的遗忘。

三级纪律 —— **照抄即可**：

```
① 能拿到精确位置 → 写精确位置
② 拿不到 → 写「位置未知」+ 容器标识 + 一个检索入口
③ 绝不猜 —— 错的门牌比没有更坏
```

★ 为什么第 ③ 条单独列出：**一个错的门牌会让你以为能找到，于是不去找。**
那比「找不到」坏得多。

**判据：拿一个被压缩过的会话，随机挑一条摘要，问「这条从哪来」。
三十秒内答不出来，门牌就是断的。**

### 2. 一门只回指针、不做转述的检索入口

转述是二手污染的来源。**能逐字取回，就不要摘要。**

动词最少三个：`现在是什么状态` / `搜一个词` / `打开某个指针`。

★ 一个细节值得抄：**检索结果里标明证据等级**（一手 / 索引 / 程序）。
一屏里同时出现三种来源时，用户必须一眼能看出哪一句是原文、哪一句是转述。

### 3. 一个自检（哨兵）

**判据 ③ 的落地**：它坏的时候，谁会发现？

体检项要跑得起来、要能给出分级状态（正常 / 提示 / 警告 / 错误）。
**没有哨兵的体系，坏了不会有人说。**

★ 哨兵最容易漏的一种失败：**它自己坏了。**
所以哨兵也要能被一个外部动作验证 —— 否则你只是把「没人知道」换成了「一个同样没人知道的东西说没事」。

## 五、观测面 · 一个容易被漏掉的洞

**你的每一个执行器都要有对应的观测面。** 一个调好就不再看的阈值系统，
你永远不会误伤过几次 —— 「断过没有、断错没有」必须有人能答。

压缩这一层尤其如此：**压缩不会报错，它只会成功地丢掉东西。**
所以你要看到的不是「压缩成功 / 失败」，是**「这次压掉了多少、压掉的那部分还能不能找回来」**。

## 六、怎么知道自己已经退化了（三条可执行的检验）

这一层的难点在于**它坏的时候不疼**。所以需要主动测，不能等它疼。

**检验一 · 门牌抽查**
拿一个被压缩过的会话，随机挑三条摘要，看能不能通过门牌回到原文。
一条回不去，链条就是断的。

**检验二 · 逐字核对**
找一条你「记得」的事实，去一手层核对原文。
如果原文和你记得的不完全一致 —— 不是记错，是压缩时偏了，而且你一直没发现。

**检验三 · 三份真相计数**
同一个事实，你手里有几条来源？
超过一条，说明权威源没定；这时候你每一次引用都在做一次隐性的仲裁。

★ 三条都不需要特殊工具，需要的是**愿意去测**。
而愿意去测的前提，是你知道自己可能已经坏了 —— 这正是这一节存在的理由。
