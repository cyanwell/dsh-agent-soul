# Ⅱ · VITAL —— 稳态

**它管时间与方向。** 三种资源都会耗尽，而它做的都是同一件事：

> **把偏离拉回来（homeostasis）。**

## 三种资源，各自要有 传感器 + 执行器 + 设定点

| 资源 | 失败模式 | 你要有的 |
|---|---|---|
| **空间**（上下文） | 丢的东西找不回来 | 水位分段 + 每段的权责（谁来压、谁来兜底） |
| **时间**（预算 / 轮数） | 烧光预算一个字没出 / 原地打转 / 永不结束 | 跨调用判定 + 流内切断 + 切断后怎么办 |
| **方向**（目标） | 空转（该停不停）/ 半途而废 | 一个「什么算做完」的判据 |

## ★ 一条设计风格，值得照抄

**每一条阈值背后都应该挂着一个具体的 bug。**

不要为了「稳」去拍一个数字。那个数字应当能回答：「它防的是哪一次具体的失败？」
答不上来的阈值，会在某天误伤你自己，而没人知道为什么。

## 三种资源的执行器长得很像，但症状不同

```
空间不够 → 症状是「我记不全了」
时间不够 → 症状是「我在原地打转」/「我一个字都说不出来」
方向不对 → 症状是「我该停了却还在跑」/「我差一步就完了却停了」
```

★ 症状不同 ⇒ **检测法必须分开**，不能用一个「忙/不忙」的指标糊过去。

## 一条容易踩的坑

**稳态不等于「越保守越好」。** 把阈值设得极紧，你会频繁被打断；
而那本身是一种失败 —— 它让你**做不完任何需要连续思考的事**。
