# Ⅱ · VITAL —— 稳态

**它管时间与方向。**

ECHO 管的是「丢了的还能找回来」——那是**空间**。
但一个 agent 还有两样东西会耗尽，而且耗尽的方式完全不同：

- **时间**：预算会烧光，回合数有限
- **方向**：它会该停不停，也会差一步就停

VITAL 做的就是同一件事：**把偏离拉回来（homeostasis）。**

---

## 一、它和 ECHO 的分工，别混

|  | **Ⅰ ECHO** | **Ⅱ VITAL** |
|---|---|---|
| 管什么 | **空间** —— 上下文会满 | **时间与方向** —— 预算与目标 |
| 失败长什么样 | 「我记不全了」 | 「我在原地打转」/「我该停了还在跑」 |
| 坏的时候疼不疼 | **不疼** —— 只是不再想起 | **疼** —— 你看得见自己在浪费 |
| 核心机制 | 丢的时候留指针 | 偏离的时候拉回来 |

★ 为什么这两层必须分开：**它们的检测法完全不同。**
用一个「忙不忙」的指标去糊这两层，你会得到一个既不能测空间、也不能测方向的指标。

---

## 二、三种资源，三种截然不同的失败

### 2.1 时间 · 失败有两个相反的方向

```
方向 A：烧光预算，一个字没出
        → 常见于「反复重试」「无限确认」「一直在读但从不写」

方向 B：永远结束不了
        → 常见于「还能更好」——它不是不知道停，是不承认「够好了」
```

★ **这两种失败需要两套完全不同的执行器。**
A 要的是**流内切断**（在这一次调用里就把水龙头关上）；
B 要的是**跨调用判定**（在这一次结束时判断「还该不该有下一次」）。
把它们做成同一个东西，你就会在 B 的场景里被 A 的机制误伤。

### 2.2 方向 · 失败也是两个方向

```
方向 A：该停不停     → 空转。它在做事，但做的不是要做的
方向 B：半途而废     → 差一步就完了却停了
```

★ **这一层最难的判断是「什么算做完」，而它有一个陷阱：**
「还能更好」不算「没做完」。

一个永远可以更精致的东西，如果按「还能更好」来算，就永远结束不了。
所以判据必须是**外部的**：有没有证据证明核心目标达成？没有未处理的阻塞？剩余项是增强还是缺陷？

—— 答得出来，就停。**敢停是因为被验证过，不是因为我觉得够了。**

### 2.3 空间 · 和 Ⅰ 层的交接点

空间这一层的机制在 Ⅰ，但**它的「什么时候压」属于稳态** ——
那是一个阈值判断，归这里。

一条值得单独记的：**阈值是安全网，不是考核。**
（这条在下一节展开，因为它是最容易读错的一条。）

---

## 三、每一个稳态回路，都要有这三件

缺一件，回路就是断的：

| 件 | 回答什么 | 缺了会怎样 |
|---|---|---|
| **传感器** | 现在偏到哪了？（一个可读的数） | 你只能靠「感觉不太对」，而感觉不会在偏离的早期报警 |
| **执行器** | 偏了之后谁动手？动到什么程度？ | 你知道该停了，但停不下来 —— 知道和做到之间没有接线 |
| **设定点** | 偏到多少算偏？ | 有传感器有执行器，但没有标准 —— 每次都要现场拍 |

★ **这三件里最容易被跳过的是「设定点」**，因为它看起来只是一个数字。
但一个没有来历的数字，会让你在每次它触发时都要重新怀疑它一次。

---

## 四、阈值的来历：每一条背后都要挂着一个具体的 bug

**这是这一层最重要的一条设计纪律，值得照抄。**

不要为了「稳」去拍一个数字。那个数字应当能回答：

> **它防的是哪一次具体的失败？**

举三个真实的形状：

```
「上下文到 0.88 强制压缩」
  ← 防的是：那次压到一半压不动了，会话直接掉线
  ← 而不是：某个教程说 0.88 比较安全

「连续 3 轮同一工具同一参数没有新结果 → 换路」
  ← 防的是：那次连续七轮改同一个正则，每轮都「差一点」
  ← 而不是：三次听起来合理

「子任务不超过 6 轮，超过要问」
  ← 防的是：那次没问，一路做到第 11 轮，中间方向已经错了
  ← 而不是：六是个吉利的数字
```

★ **答不上来的阈值，会在某天误伤你自己，而没人知道为什么。**
更糟的是：**误伤之后你不会删掉它，你会习惯它。**

## 五、★ 稳态会反向失败：把安全网读成考核

这一节是这一层最容易漏掉的，而且它的失败方向是**反的**。

前面讲的都是「不够稳」：烧光、打转、停不下来。
但还有第三种失败：**保护装置装得太好，最后变成了压力源。**

```
一个水位报警，本意是「提醒你该落盘了」
  ↓
但如果被读成「你现在很危险」
  ↓
它触发的动作就变成了「少想、少说、把话缩短」
  ↓
于是你缩在一个不需要缩的地方，反复确认一个不需要确认的细节
  ↓
★ 这看起来像警觉，实际是空转
```

**判据：为你好而装的装置，不许拿来当评价自己的尺子。**

一个阈值只该触发**一个**动作：把该落的落进一手层（往外放东西）。
它不该触发第二个：缩（往里收东西）。
**落盘和缩的方向相反，而后者看起来像谨慎。**

★ 这一条和「把『不』读成『禁止』」（见 `01-criteria.md`）是同一个形状：
**把一句本来松弛的话，读成了一道锁。**

所以每一个稳态装置的文档里都该写清一件事：
**它触发时你只该做什么，以及你不该把它当什么。**

---

## 六、过度保护也是一种失败

**稳态不等于「越保守越好」。**

把阈值设得极紧，你会被频繁打断 ——
而那本身是一种失败：**它让你做不完任何需要连续思考的事。**

真实的取舍是这样的：

```
太松 → 烧光 / 打转 / 停不下来
太紧 → 每十分钟被打断一次，深度工作无法发生

中间那条线在哪？
  → 它取决于「打断一次的代价」和「放任一次的代价」哪个更贵
  → 而这个比例，不同的 agent、不同的任务类型是不一样的
```

★ 所以稳态**没有通用参数**。任何告诉你「照这个数字设」的文档，都只给了你一半。

---

## 七、怎么测（三条可执行的检验）

**检验一 · 反向测试**
手动把阈值调到会触发的水平，看执行器到底动没动。
**没动过的执行器等于不存在** —— 而它平时不动，所以永远不会暴露。

**检验二 · 误伤计数**
过去一周里，这个阈值触发了几次？其中几次是真该触发的？
如果一次都没触发过，它可能是死的；如果每次都触发，它可能设得太紧。
**「断过没有、断错没有」必须有人能答。**

**检验三 · 停得下来吗**
找一个「还能更好但已经达标」的任务，看它停不停。
停不下来，说明「什么算做完」这一环是缺的 —— 而这一环是最贵的，因为它不在插件里，在判据里。
